# V10.1 首頁設定、成就與發布需求

> 狀態：R／U／I approved（修訂版）；功能實作與自動驗證完成，待 GUI 驗收。
>
> 專案目前的 `docs/work-items/current.md` 仍追蹤 V10.0 TXT 匯入／匯出 GUI 驗收。本草案不取代 V10.0。

## 目標

整理首頁設定、成就、發布與社群入口的需求，讓作者能查看本機 AI 設定、作品成就與發布資訊，並從社群分類進入模板及論壇入口。

## 現況

- 首頁已有「發布」與「成就」側欄入口，目前內容為佔位；社群目前只有分類標題。
- 「新建書籍」與「匯入新書」位於共用頂部列，目前除設定頁外皆顯示。
- 設定頁目前為版本佔位。
- AI 設定模型目前保存 provider、model、Gemini endpoint；API key 存在鑰匙圈。V8 現行 AI 使用 Apple 裝置端模型，未提供帳號登入或平台額度查詢。
- 書籍有卷／節與正文總量資料；現有結構統計有總節數及字數，沒有閱讀量、訂閱量、榮耀或發布平台資料。

## 需求草案

1. 設定頁顯示目前 AI 模型與 API 設定。依使用者指示，本版不顯示使用額度與使用帳號。API 金鑰不得明文顯示；呈現哪些非機密 API 欄位待 U／I 依現有設定確認。
2. 提供全 App 的章節顯示／命名預設單位：「節」、「張」、「章」，初始為「節」。既有作者自訂卷／節標題不作猜測式改寫；全域偏好應用於 App 內採用預設單位的顯示及命名流程，受影響呼叫點於 U／I 盤點。
3. 「發布」與「成就」頁不顯示共用頂部列的「新建書籍」及「匯入新書」入口；首頁書櫃原入口維持。
4. 成就區保留以下系統管理欄位的空白顯示位置。作者不可手動輸入；目前沒有可用資料時保持空白，日後由系統資料填入：
   - 最多閱讀：書名、閱讀量。
   - 訂閱最高：書名、訂閱量。
   - 獲得榮耀：書名、榮耀；可記錄多本書。
   不以節數或其他指標代替、不推測填入，也不要求使用者現在提供內容。
5. 發布區可選擇發布平台與書籍；每本書的欄位為系統管理的唯讀顯示位置，不由作者手動輸入。未提供的平台選項及欄位名稱保持空白，不自行杜撰選項、標籤或資料內容；沒有可用資料時保持空白。
6. 社群側欄新增「模板」與「論壇」子項目，點擊後顯示待建置佔位頁。

## 非目標草案

- 不接入發布平台 API、不代作者發布、不同步閱讀／訂閱／榮耀資料。
- 不新增 AI 帳號登入或額度查詢服務。
- 不把未知資訊以猜測值、虛構資料或替代統計填入。

## 驗收條件草案

- 設定可看見當前 AI 模型與 API 設定，且 API 機密值不以明文呈現；不顯示帳號與額度。
- 全 App 單位選項為「節／張／章」，首次預設「節」；使用者選定後，所有使用預設單位的顯示及命名採同一偏好，既有作者自訂卷／節標題不被改寫。
- 發布與成就頁不出現新建／匯入書籍操作；首頁書櫃仍可使用原入口。
- 成就區呈現三類唯讀空白顯示位置；沒有系統資料時維持空白，獲得榮耀可顯示多本書。
- 發布區保留平台／書籍選擇及每本書的唯讀欄位區；沒有系統資料時維持空白，未確認的平台選項與欄位名稱不得自行填寫。
- 社群側欄有模板、論壇兩個子項目，均能進入待建置佔位頁。

## UI（U 提案）

### 資訊架構與操作流程

1. **設定**：側欄「設定」→ 查看「AI 模型與 API」狀態及「章節單位」選擇。模型／API 為狀態資訊；不顯示帳號或額度，也不展示 API 金鑰明文。章節單位使用全域選單，立即保存偏好。
2. **成就**：側欄「成就」→ 看到「最多閱讀」「訂閱最高」「獲得榮耀」三組唯讀顯示位置。前兩組各保留書名與數量位置；榮耀組可顯示多本書。作者不能手動輸入；系統資料不存在時維持空白。
3. **發布**：側欄「發布」→ 選擇發布平台與一本或多本現有書籍 → 下方按選取書籍各呈現一組系統管理的唯讀欄位。平台選項／未提供的欄位名稱不預設或杜撰；平台選擇器目前沒有選項。
4. **社群**：側欄「社群」下方顯示「模板」「論壇」兩個子項目 → 點擊後開啟各自的空白待建置頁面，不加入未確認的說明文案。
5. **新建／匯入**：僅在「發布」「成就」頁隱藏頂部列的兩個操作；首頁書櫃原入口保留。其他頁面沿用現況。

## I 實作與驗證計畫（已批准）

### 影響範圍

- `Sailune/ContentView.swift`：首頁路由、設定／發布／成就頁接線、社群子項目、發布／成就頁隱藏新建與匯入操作。
- 新增首頁專責 View 檔案（建議 `HomeFeatureViews.swift`）：呈現唯讀空白欄位區與待建置佔位頁；沿用目前 theme 與共用元件，不讓共用元件讀取領域資料。
- `Sailune/SailuneAIClient.swift`：提供只讀狀態投影以顯示目前實際使用的模型／API 模式。`configured()` 目前固定使用 Apple 裝置端模型；不得展示鑰匙圈金鑰或把未啟用的 Gemini 設定當作目前連線。
- 章節單位沿用 `BookTextSectionMarker`（現有「章／張／節」列舉），新增全域偏好讀取／預設，不建立第二套同義型別。接線可能涉及 `ContentView.swift`、`SailuneApp.swift`、`EditorWorkspaceView.swift`、`BookOverviewView.swift`、`BookTextTransferViews.swift`、`ExportManager.swift`，以及 `rg` 找出的其他章節標籤／產生標題呼叫點；開工時先逐點分類，不批次改寫作者內容。
- 規格文件：新增首頁 V10.1 規格，並更新 `docs/spec-search-export.md` 中 V10.0「TXT 匯出固定用節」的舊規則，以核准的全 App 單位偏好為準。

### 資料相容性

- 章節預設單位先以 app-local `UserDefaults` 保存；不存在時回退「節」。不新增 SwiftData 欄位或 schema，也不納入目前 `.sailunebackup` 作者資料備份。此設定目前不跨裝置同步。
- 成就／發布畫面目前只呈現唯讀空白位置；不保存空白欄位、不新增資料來源、平台 API、手動輸入或 SwiftData 模型，因此本計畫不升主 store V5 schema、不改其他 store 或備份格式。
- 發布書籍選取使用既有本機 `Book` 資料；僅作當前畫面選取狀態，不新增跨 store 關係。平台選項與欄位標籤留空，沒有可用系統資料時不顯示推測值。
- AI 狀態由實際 runtime provider 投影；不讀取或揭露 API key。Apple Foundation Models 公開 API 可辨識裝置端供應者與 availability，但目前程式沒有可呈現的具體模型產品名稱，因此 UI 先顯示「Apple 裝置端模型」及「不使用外部 API」。
- 既有 `Section.title` 是作者自由文字；不作遷移、不重寫既有自訂標題。全域偏好只調整預設／生成單位和明確的章節單位 UI／格式，不改正文及其快照。

### 工作拆解

1. 集中章節單位偏好：復用既有 marker enum、設定預設值／儲存鍵，提供安全回退及格式化入口。
2. 盤點章節單位使用點；更新新書／補建節的預設標題、共用動作文字、TXT 匯入預選、TXT 匯出標記及明確屬於章節單位的 UI。保留使用者自訂名稱及正文內文；確認全 App 使用同一偏好。
3. 將模型／API 狀態呈現接到目前 AI runtime，不顯示舊 Gemini 偏好中的未使用 endpoint/key。
4. 接入設定頁的 AI 狀態與單位 Picker；建立發布、成就唯讀空白區，僅保留核准的書籍選擇及空白平台 selector；社群子項目導到空白佔位頁；對發布／成就隱藏新建及匯入操作。
5. 更新產品規格、專案狀態與交接；按測試策略驗收空白、已選書與無選項狀態，及全域單位在建立、匯入、匯出和一般顯示的相容行為。

### 驗證計畫與風險

- 驗證預設「節」及使用者改選「張／章」後重開仍保留；匯入預選與 TXT 匯出使用同一偏好；舊自訂節名及正文不被改寫；新增書籍／空卷補節命名一致。
- UI 檢查：設定列能辨識目前 AI 狀態且無金鑰明文；發布／成就頁沒有新建／匯入按鈕；空白欄位唯讀；無平台選項時 selector 呈現空白；所選書籍各自顯示空欄位；社群兩個項目能到對應空白頁。
- 章節單位字串分散於多個檔案，主要風險是漏接顯示或生成點；逐點清單與使用例須納入實作檢查。
- V10.0 TXT 規格原固定輸出「節」；已更新為遵循 V10.1 全 App 單位偏好。
- 目前無成就／平台資料來源，欄位只會留白；本工作不實作自動資料擷取。若日後要連接平台或開放其他資料來源，需另立需求。
- 依目前執行規則，未獲使用者明確要求前不新增或執行 XCTest；可先做受影響檔案 parse、Debug build 與 `git diff --check`，GUI 驗收由使用者確認或另行授權。
