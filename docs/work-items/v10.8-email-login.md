# V10.8 Email 登入入口

> 狀態：active；依使用者明確實作指示開始，採用 `docs/pagelet-auth-contract.md` v0.1 已決定的登入契約。

## 工作單位

- **目標**：在帆夢現有帳號入口提供拾頁共用 Supabase Auth 的 Email 驗證碼登入。
- **流程**：輸入 Email → 寄送 6 位數驗證碼 → 驗證並登入；支援重寄與登出。
- **登入後狀態**：只顯示登入中的 Email；不查詢角色、作者綁定、方案或其他帳號資料。
- **範圍**：官方 `supabase-swift`、鑰匙圈 Session、build settings 的 Supabase URL／publishable key、帳號入口及 OTP 表單。
- **非目標**：密碼／magic link、Google／Apple、角色／作者資料、作者綁定、發布／讀者數據 API、Supabase 專案設定及後端修改。
- **資料安全**：Session 僅由 SDK 存在 macOS 鑰匙圈；不寫入 SwiftData、UserDefaults、sidecar 或 `.sailunebackup`。未設定連線資料時，本機功能照常使用，登入畫面提示服務未設定。
- **批准記錄**：使用者明確要求依登入契約增加 Email 登入入口並允許登入後不呈現其他狀態；依 AGENTS.md 的明確具體變更例外直接實作。流程依現有帳號入口與文件已定義 OTP 步驟，不擴增其他 UI。
- **共用欄位例外**：Email 欄需設定 `.emailAddress` autofill content type，驗證碼欄需設定 `.oneTimeCode` 並即時限制 6 位數；現有 `SailuneFormTextField` 不暴露這些輸入契約，因此兩欄保留 feature-local 原生 `TextField`，沿用系統 rounded border。
- **驗收**：帳號入口可進 Email／驗證碼流程；可送碼、重寄、驗證、重開後恢復 Session、登出；錯誤不顯示 token、金鑰或服務原始回應；離線時本機寫作功能不受影響。
- **尚待外部設定**：工作開始時契約所記 Supabase Email 範本／自訂 SMTP 未完成；本機 build settings 尚無專案 URL 與 publishable key。設定完成前不能執行真實寄碼登入驗收。
- **驗證結果**：官方 `supabase-swift` 2.55.2 套件解析完成；無簽章 macOS Debug build 通過；受影響 Swift parse 與 `git diff --check` 通過。本輪未執行 XCTest 或 GUI。

## 設定接線修正（2026-09-27）

- 隔離驗證發現登入 client 無法建立的真正原因：自訂 `Config/Sailune-Info.plist` 沒有 `SailuneSupabaseURL`／`SailuneSupabasePublishableKey`，`INFOPLIST_KEY_*` 設定未注入此自訂 plist。已在 plist 加入由 build settings 替換的兩個值，並以 `Config/Sailune-Auth-Defaults.xcconfig` 加入被 Git 忽略的 `Config/Sailune-Auth-Local.xcconfig` 保存本機值；追蹤中的 Xcode 專案不含 URL 或 key。
- `.xcconfig` 會將 `//` 當註解，故本機 URL 以 `https:/$()/...` 寫法避免截斷，Xcode 展開後為一般 HTTPS URL。
- 無簽章 macOS Debug build 通過；檢查隔離建置產物確認 URL 為 HTTPS 且含 host、publishable key 存在且格式正確；`git diff --check` 通過。尚待使用者以 Xcode 執行此版 App，確認登入畫面不再顯示「登入服務尚未設定」後，才測試寄碼／驗證／鑰匙圈 Session。未執行 XCTest。
