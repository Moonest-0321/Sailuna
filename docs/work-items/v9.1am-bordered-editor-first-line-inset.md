# V9.1am 圓角多行欄位首行安全內距

> 狀態：active（R approved；U pending；I pending）
>
> 工作單位：依使用者截圖修正地點簡介首行貼近／碰觸上邊框，並決定相同共用編輯器的採用範圍。

## 實際證據與現況

- 使用者 2026-09-25 提供的 [地點「簡介」首行截圖](../assets/v9-place-intro-first-line-clipping-2026-09-25.png)顯示「你好」首行頂部幾乎貼在圓角欄位上邊框。
- `PlaceDetailView` 的 `settingTextArea(title: "簡介", detail: "列表與快速查找使用的短摘要。", text: $place.placeDescription)` 呼叫 `SailuneBorderedTextEditor`；該共用元件現為 `TextEditor` → `frame(minHeight:)` → 圓角 `overlay(stroke:)`，沒有明確內距。
- 同一 wrapper 另由地點詳細描述／備註、世界條目簡介／詳細描述／備註，以及勢力描述、目的、關係等欄位呼叫。來源碼有六個 wrapper 呼叫點，實際欄位種類超過六種。
- 截圖與來源碼支持「首行安全距不足」的判斷；尚未以實際 App 驗證所有欄位、字體大小、Light 外觀及游標／捲動狀態。

## 精確 UI 提案

保持標題「簡介」、說明、Binding、欄位外框位置、8 pt 圓角、現有描邊顏色與原最小高度。由共用編輯器在描邊內提供水平 9 pt、垂直 8 pt 的文字安全距，背景仍使用原生文字欄背景；長文維持在欄位內捲動，不使用 offset 或放大高度掩蓋首行問題。

```text
目前：  ┌你好─────────────┐  首行幾乎碰到上框
提案：  ┌─────────────────┐
        │  你好           │  左側約 9 pt；上方約 8 pt
        │                 │
        └─────────────────┘
```

**採用範圍待 U 核定**：建議在 `SailuneBorderedTextEditor` 內統一修正，讓地點、世界條目與勢力等相同圓角多行欄位均受益；若只核定地點簡介，則在共用元件增設具名 inset variant 並只在該欄採用，不讓其他欄位外觀改動。

## 非目標與相容性

- 不改 `InsetTextEditor`、單行 `SailuneFormTextField`、正文 AppKit `NSTextView` 或其他手動 placeholder editor。
- 不改文字內容、資料欄位、保存時機、驗證、組字、選取及 Undo 邏輯。
- SwiftData schema、資料遷移、地點關聯與刪除行為不變。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved | 使用者明確要求修正首行穿模，並提供地點簡介的實際畫面。 |
| U | pending | 上述數值、背景維持與共用採用範圍待核定。 |
| I | pending | U 核定後才修改共用 editor；需檢查受影響呼叫點與畫面。 |

## 完成條件與驗證計畫

1. 截圖中的地點「簡介」首行、placeholder、游標與選取均與圓角描邊保持可讀距離；長文捲動起點不貼框。
2. 依核定範圍核對地點、世界條目與勢力代表欄位的 Light／Dark、空值、繁體中文、焦點、組字及 Undo；無法驗收的項目明列，不以 build 代替 UI 證據。
3. `git diff --check` 與主機無簽章 macOS Debug build 通過；本工作不新增或執行 XCTest。
