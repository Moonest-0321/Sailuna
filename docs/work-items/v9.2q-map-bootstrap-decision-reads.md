# V9.2q 預設地圖初始化的決策查詢

> 狀態：closed（預設地圖初始化與地圖標記建立的必要讀取已傳遞錯誤）
>
> 工作單位：地圖首次進入及從地圖建立標記時，查詢失敗不可被當成沒有既有資料或排序從零開始。

## 現況與完成條件

- `ensureDefaultMap` 原先把地圖／版本／placement／Place 的列表查詢錯誤當成空清單；未初始化分支更在這些查詢之前先插入 `MapCatalogProfile`。失敗可能使流程誤建地圖、版本或重複回填 placement。
- `createMapPlace` 原先以 nonthrowing `places(for:)` 取得下一個排序值；查詢失敗可能把新 Place 排在第一筆。
- 本批讓預設地圖流程的 profile、地圖、版本、placement 與 Place 必要讀取先完成，之後才插入 profile／地圖／版本／placement；地圖標記建立的排序讀取改為可拋錯。正常無資料、已初始化但地圖被刪空、合法舊座標轉換與 PDF 遷移時機保持原規則。
- 不改 SwiftData schema、地圖 UI、一般畫面列表 API、跳轉前來源標記查詢、主 store 與地圖資產的保存／回滾政策。

## 驗證與限制

- 2026-09-24：主機無簽章 macOS Debug build 與 `git diff --check` 通過。未執行程式測試、故障注入、實際初始化或 GUI 驗收；建置只證明程式可編譯。
- `ensureDefaultMap` 仍先保存 SwiftData，再嘗試舊 PDF 搬移；該資產錯誤的重試政策及畫面載入失敗呈現不在本批範圍。
- V9.2c 仍需處理跳轉前的來源 Place／placement 讀取及畫面列表的「讀取失敗 vs 真正空清單」。
