# V9.2r 標記跳轉的來源查詢

> 狀態：closed（跳轉來源讀取失敗會停止操作）
>
> 工作單位：從現有地圖標記跳轉下層地圖時，來源 Place 與 placement 必須可讀取且彼此相符，才進入目的地配對。

## 現況與完成條件

- `MapWorkspaceView.navigateFromMarker` 原先透過 `places(for:)` 與 `placements(for:)` 的 nonthrowing 列表尋找來源；任一查詢失敗都會變成 `invalidNavigationSource`，無法區分資料讀取失敗與標記不存在。
- 新的 `V5SettingsStore.markerSource` 以可拋錯查詢讀取 Place 與 placement，確認同書、同地圖及 placement 指向該 Place；跳轉時真正找不到來源仍回報原 `invalidNavigationSource`。
- 兩個查詢與關聯核對完成後才呼叫原 `destinationMap`；資料讀取失敗不會建立目的地或改寫來源綁定。既有標記編輯器 `onNavigate` 與錯誤顯示入口保持。
- 不改地圖畫面、跳轉層級／名稱規則或 SwiftData schema。標記編輯來源另由 V9.2s 處理；刪除流程未改。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved | 使用者要求完成 V9 資料操作規範；本批只讓既有 throwing 跳轉鏈保留來源查詢錯誤。 |

## 驗證與限制

- 2026-09-24：主機無簽章 macOS Debug build 與 `git diff --check` 通過。未執行程式測試、故障注入、實際跳轉或 GUI 驗收。
- 地圖／版本／placement 畫面列表的讀取失敗仍可能顯示空狀態；這與本批跳轉決策分開處理。
