# V9.2c 跨 Store 建立與地圖查詢失敗路徑

> 狀態：active（錯誤記錄範圍已核定；操作結果政策另議）
>
> 工作單位：把兩條目前可能隱藏部分成功或查詢失敗的資料流程，設計為可診斷、可驗收的操作邊界。

## 現況與問題

1. `InspectorViews.swift` 的 `addAbility()` 先把 `CharacterAbility` 存入主 SwiftData store，再以 `AbilityProgressStore.register` 存入 `AbilityBookLink`。若第二步失敗，View 刪除能力並嘗試補償；若補償保存又失敗，V9.2c 已記錄該次錯誤，但仍呈現原始 register 錯誤。`AbilityProgressStore.register` 會 rollback 自己的 context、reload 並重新拋錯，主 store 的補償結果仍無法由呼叫端分辨。
2. `PersistentStoreRepair.repairCharacterHierarchy` 明確保留 `character == nil` 的能力，因為其書籍歸屬可能稍後由 `AbilityBookLink` 提供。跨 store 修復使用 `resolvedBookIDs` 與有效 ID 清理附屬資料；它沒有足夠證據自動判斷「無 link 的新能力」該補 link 還是刪除。因此不能宣稱啟動修復必會消除這種部分成功。
3. `MapCatalog.swift` 的 `maps`、`versions`、`placements` 三個查詢曾以 `try? fetch ?? []` 把資料庫查詢失敗回傳為空清單；目前已加 OSLog 記錄並維持空清單結果。這三個 API 除供地圖及管理畫面顯示，還參與 `ensureDefaultMap`、同名檢查、最後版本刪除防護、標記編輯與跳轉。失敗時可能被誤認為無地圖、無重名、無版本或無標記；這是來源碼上的可能路徑，尚未以故障注入重現。

## 原操作結果提案（尚未核定）

- 能力建立只在主能力與書籍連結皆保存後視為成功；主保存失敗、link 保存失敗且補償成功、link 與補償皆失敗，需有可區分的結果。最後一種情況須保留能力 ID 與兩個底層錯誤供診斷，並有明確的後續修復入口；不可吞掉補償錯誤或把部分成功顯示為完全失敗後任由重試建立重複能力。
- 地圖「真正空清單」與「無法查詢」必須可區分。所有會建立、改名、刪除、導航或選擇地圖／版本／標記的流程，在必要查詢失敗時停止動作並呈現既有錯誤出口；不得據空陣列繼續寫入。正常空清單及使用者刻意刪除所有地圖的狀態維持原產品行為。
- 不改 SwiftData schema、既有資料關係、地圖層級規則或 UI 排列。跨 Store 部分成功的復原政策與錯誤呈現字句須在實作前確認。

## 原始行為提案（操作結果政策待後續決策）

| 流程 | 最小責任邊界 | 需要的失敗情境 |
|---|---|---|
| 能力建立 | 具名 coordinator 接收主 `ModelContext`、`AbilityProgressStore`、book ID；回傳能力或具型別的主保存／link／補償失敗，View 只負責觸發與顯示 | 主保存失敗；link 保存失敗且主能力已刪除；link 與補償保存皆失敗；同一能力 ID 重試／修復 |
| 地圖查詢 | 保留畫面可讀取快照的方式，但為決策型讀取提供可拋錯 API；`ensureDefaultMap`、驗證與破壞性操作不得再使用吞錯空陣列 | 空書籍／空地圖；各 fetch 失敗；已初始化但刻意刪空；同名驗證；最後版本防護；marker 查詢失敗時編輯／跳轉停止 |

### 使用流程草案

- 能力建立：點「新增能力」→ 兩個 store 均成功才出現新能力；主保存或已完整補償的失敗沿用「能力建立未完成」錯誤；部分成功需明確告知「資料保存未完成」與可採取的修復動作，不可直接讓使用者重複新增。
- 地圖：正常空清單仍顯示既有空狀態；讀取失敗顯示錯誤並保留目前選取，不把畫面重設成「沒有地圖」。會寫入或刪除的動作停止並回報失敗。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved（限錯誤記錄） | 使用者決定「先只記錄錯誤，不改操作結果」；跨 Store 補償與地圖空集合 fallback 的實際結果政策仍未核定。 |
| U | not_applicable（限錯誤記錄） | 本批只記 OSLog，不改畫面、空狀態或操作回應。 |
| I | approved（限錯誤記錄） | 在七類 Store reload／refresh 之外，對能力補償保存、地圖／設定列表 fetch fallback 記錄次要錯誤；保留目前回傳空陣列、丟原錯誤與操作結果。 |

## 範圍、限制與驗證計畫

- 相關檔案：`InspectorViews.swift`、`AbilityProgress.swift`、`PersistentStoreRepair.swift`、`MapCatalog.swift`、`MapViews.swift`、`MapManagementViews.swift`；資料相容性參考 `docs/data-model.md` 與 `docs/backup-and-migration.md`。
- 能力與地圖拆成兩個獨立實作切片，避免把跨 Store 補償和地圖 UI 錯誤狀態混在同一變更。
- 實作時以可控制的失敗入口核對上述情境；編譯及差異檢查只能驗證語法與接線，不能證明故障路徑。依使用者測試授權決定是否執行測試；GUI 另核對錯誤與正常空狀態。
- 使用者核定只增加錯誤診斷、不改操作結果；能力補償保存、13 個 V5 設定列表和三個 MapCatalog 列表均已記 OSLog。完整 coordinator、錯誤 UI 與空集合結果政策仍待另行核定。
