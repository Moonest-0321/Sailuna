# V9.2o 地圖與版本刪除的決策查詢

> 狀態：closed（兩個刪除入口的決策查詢已傳遞錯誤）
>
> 工作單位：地圖及版本刪除在必要 SwiftData 查詢失敗時，於任何刪除變更前停止，沿現有 throwing API 回報。

## 現況與完成條件

- `deleteMap` 原先先將版本與來源 placement 排入刪除，之後才查詢指向該地圖的來源 placement；最後查詢失敗可能留下尚未保存的部分刪除。本批先成功查到版本與同書全部 placement，再清理、刪地圖及保存。
- `deleteVersion` 原先用 `versions(for:)`，查詢失敗會折疊成零筆並誤報「最後版本」；本批以可拋錯查詢判定數量。
- 原有書籍／地圖過濾、成功刪除順序、`BookMapPDFStore` 資產清理與 `MapManagementViews` catch 保持；不改地圖規則、UI 排列、schema 或正常空清單語意。

## 驗證與限制

- 2026-09-24：`deleteMap` 的版本與同書 placement 查詢在任何刪除／解除綁定前完成；`deleteVersion` 用 `try fetch` 檢查剩餘版本。失敗沿既有 `MapManagementViews` catch 回報；成功後的 store save 與 PDF 清理順序不變。
- `git diff --check` 與主機無簽章 Debug build 通過；未執行程式測試、故障注入或 GUI 驗收。
- `maps`／`versions`／`placements` 其餘顯示、建立、改名和跳轉決策仍使用可能吞錯的列表 API，依 V9.2c 另行處理；本批不宣稱完整地圖錯誤流程完成。
