# V9.2s 既有標記編輯的來源防護

> 狀態：closed（來源讀取失敗或來源不存在時，不再建立新標記）
>
> 工作單位：編輯既有地圖標記時，必須確認原 Place 與 placement 存在且彼此相符，才能更新；失敗時維持原資料。

## 現況與完成條件

- `MapWorkspaceView.saveMarker` 原先用兩個 nonthrowing 列表尋找既有 Place／placement；任一列表查詢失敗或資料缺失，就落到新標記建立分支，可能產生重複 Place 與 placement。
- 本批沿用 V9.2r 的 `markerSource` 可拋錯查詢。draft 有任一來源 ID 時視為編輯，不允許轉成新增；兩個 ID 及其同書／同地圖關聯需完整，否則在寫入前停止。
- 來源真正不存在時，現有「無法完成操作」alert 顯示「找不到原有地圖標記，請重新載入地圖。」；SwiftData 讀取錯誤則顯示原底層錯誤。兩個 ID 都沒有時仍走原新增流程。
- 不改標記位置、編輯欄位、保存內容、刪除行為、SwiftData schema 或 UI 排列；標記刪除仍有獨立的 nonthrowing 來源查詢待評估。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved | 使用者要求完成 V9 資料操作規範；本批避免編輯失敗意外建立新資料，保留新增與更新的既有正常行為。 |
| U | not_applicable | 仍使用既有錯誤 alert；只在原資料已不存在時提供具體錯誤文字，不改控制項或正常畫面。 |
| I | approved | 在 `MapWorkspaceView.saveMarker` 區分既有 ID 與新 draft，重用地圖 store 的可拋錯來源查詢。 |
