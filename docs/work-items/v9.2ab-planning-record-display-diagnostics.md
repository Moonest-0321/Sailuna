# V9.2ab 規劃紀錄投影顯示診斷

> 狀態：closed
>
> 工作單位：讓時間軸與大綱兩處相同的投影查詢 fallback 共用單一診斷入口，保留現有空清單結果。

## 現況與邊界

- `TimelinePanelView.planningRecordProjections` 與 `OutlineStructureBoardView.planningRecords` 均呼叫 `PlanningRecordProjectionBuilder.build`，兩處都以 `try?` 在失敗時回傳 `[]`。
- `build` 的 throwing API 及其測試呼叫保留；新增供既有顯示畫面使用的 `buildForDisplay`，記錄來源與失敗原因後回傳空清單。
- 本批不改資料查詢、排序、過濾、空狀態、畫面出口、保存或 schema。查詢失敗和真正空資料的產品呈現政策仍待另議。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved | V9 錯誤稽核要求可診斷；使用者決定目前先記錄錯誤，維持操作結果。 |
| U | not_applicable | 不改畫面、文字或互動。 |
| I | approved（限診斷） | 兩個呼叫端回傳值、投影 builder 正常路徑與 throwing API 均維持原樣。 |

## 完成條件

- 兩處 fallback 只透過共用診斷入口處理，來源可分辨時間軸與大綱，日誌不帶書籍內容或 UUID。
- 正常建置的投影、失敗時 `[]` 的結果與原畫面表現不變。
- `git diff --check` 與主機無簽章 Debug build 通過；不新增或執行 XCTest。

## 結果

- `PlanningRecordProjectionBuilder.buildForDisplay` 在原 throwing `build` 外集中 `do/catch`；時間軸與大綱各傳入固定來源，錯誤細節採 private OSLog，沒有書籍內容或 UUID。
- 兩個 View 仍回傳 `[]` 並沿用既有空狀態；原 throwing `build` 及測試呼叫不變。
- `git diff --check` 與主機無簽章 macOS Debug build 通過；全專案 `try?` 靜態命中由 17 降至 15 處。未執行 XCTest、故障注入或 GUI 驗收。
- 查詢失敗與真正無資料是否應呈現不同 UI，待產品政策另議。
