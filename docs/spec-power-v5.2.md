## 現況與問題

- 現行勢力先指定層級，再以直接隸屬連線保存多上級與多下級關係。
- 現行詳細頁同時提供「新增上層」與「新增下層」，容易讓查詢列表與建立關係的入口混在一起。
- 勢力的宗教與政治目前是自由文字，尚未連接世界條目。
- 高層管理員與其他名單目前是自由文字，尚未連接既有角色，也無法逐筆保存職稱。

## 期待結果

- 建立勢力隸屬時只有一個明確流程：先選擇層級，再選擇直屬上級。
- 上級與下級列表用來查詢目前關係；解除關係由上級列表操作。
- 勢力可直接連接世界條目，不複製世界條目內容。
- 勢力成員可連接既有角色，職稱由作者自由輸入。
- 不把參考草圖實作成關係圖、表格或自由配置畫布。

## 已確認需求

### 層級與直屬關係

1. 勢力必須先指定一個層級，才可選擇直屬上級。
2. 「選擇直屬上級」是新增隸屬關係的唯一入口。
3. 直屬上級候選依既有層級方向篩選，只顯示較高層級且屬於同一本書的勢力。
4. 保留既有跨級直屬、多個直屬上級與多個直屬下級能力。
5. 不提供「新增下級」操作；下級關係由另一勢力選擇目前勢力為直屬上級後自然形成。
6. 上級與下級列表用來查詢已建立的關係，不是新增關係的入口。
7. 解除直屬關係的入口位於上級列表；移除一筆上級只刪除對應的直接隸屬連線，不刪除任一勢力或其他關係。
8. 改變勢力層級或重新排序層級若會使既有直屬關係反向或同級，仍阻止整項變更並保留原資料。

### 世界條目連接

1. 勢力本身是獨立設定，沒有「分類」欄位，也不建立勢力分類模型或有限分類選項。
2. 宗教、政體、核心、範圍是四個勢力欄位；目前只有宗教與政體直接選擇並連接既有世界條目，而且只能連接相同分類的條目。核心代表勢力實際控管的核心區域，範圍代表勢力的輻射區域，之後改為連接地點或地圖。
3. 底層使用世界條目 UUID，不複製名稱或內容。
4. 世界條目重新命名後，勢力連接保持有效並顯示新名稱。
5. 所有候選必須屬於同一本書。
6. 刪除被連接的世界條目時，解除對應連接，不刪除勢力或其他世界條目。
7. 現有宗教與政治自由文字不可猜測轉換或覆蓋；V5.2 必須保留原內容。
8. 核心與範圍目前不連接世界條目；核心代表實際控管區域，範圍代表輻射區域，地點／地圖連接留待後續版本。

### 勢力成員

1. 每筆成員選擇一本書中的既有角色，以角色 UUID 建立連接。
2. 每筆成員另有一個作者自由輸入的職稱欄位。
3. 同一角色在同一勢力先只允許一筆成員資料與一個職稱；需要變更時編輯原職稱，不新增第二筆。
4. 角色重新命名後，成員顯示同步使用目前角色名稱；不在勢力資料內保存可分歧的人名副本。
5. 刪除角色時解除對應成員連接，不刪除勢力。
6. 現有高層管理員與其他名單自由文字不可猜測拆分或覆蓋；V5.2 必須保留原內容。

## 明確非目標

- 不實作關係圖、樹狀圖、畫布或節點連線介面。
- 不保存勢力節點座標或自訂視覺排列。
- 不實作地圖、疆域繪製或地理範圍隨時間變化。
- 不在本工作建立勢力關係歷史或成員加入／退出時間軸。
- 不從自由文字自動推測角色、職稱或世界條目連接。
- 不改變既有角色、世界條目、正文、物品、能力或故事規劃的內容所有權。

## UI 提案

### 使用流程

1. 作者從既有勢力列表新增或開啟一個勢力。
2. 在勢力詳細頁選擇層級。
3. 從獨立的「選擇直屬上級」入口開啟候選清單；候選按層級由高至低顯示，並清楚標示勢力名稱與所屬層級。
4. 選擇候選後建立一筆直接隸屬；不提供從下級列表新增關係的操作。
5. 上級列表顯示目前全部直屬上級，每列提供解除入口；下級列表只顯示目前全部直屬下級。
6. 作者替宗教、政體選擇一筆相同分類的世界條目，或清除目前連接；核心與範圍顯示為之後連接地點／地圖的保留欄位。
7. 作者從同書角色清單選擇成員，輸入職稱後新增；既有成員可修改職稱或移除。

### 候選與畫面狀態

- 尚未指定層級：「選擇直屬上級」停用並提示先選層級。
- 沒有符合方向的上級：候選清單顯示無可選勢力，不顯示新增下級作為替代入口。
- 已是直屬上級：不再出現在新增候選中。
- 上級／下級為空：各自顯示「尚無直屬上級／下級」。
- 世界條目候選只顯示同一本書且分類相符的資料：宗教只列「信仰」，政體只列「制度」；目前連接名稱直接取自世界條目。
- 成員候選只顯示同一本書且尚未加入目前勢力的角色。
- 解除上級、清除世界條目或移除成員都只解除連接，不刪除來源資料。
- 保存失敗時保留畫面內容並顯示單一錯誤，不呈現已成功的假狀態。

## 必須保留

- 既有勢力 UUID、`bookID`、名稱、簡介、層級、上下隸屬及自由文字欄位。
- 現有跨級、多上級、多下級與衝突阻止規則。
- 隱藏設定集只改變導航，不刪除勢力資料。
- 產品版本與 settings schema 版本分開；只有資料模型確定後才決定是否新增 schema 快照。

## 實作與測試計畫

### Settings schema 與資料模型

1. 新增 `V5SettingsSchemaV5`，保留 V1～V4 為不可修改的遷移快照；產品版本 V5.2 與 settings schema V5 分開描述。
2. 在新版 `PowerUnit` 新增宗教、政體、核心、範圍四個可空欄位；既有 `powerWorldTermID`／`scopeWorldTermID` 欄位保留相容性，但核心與範圍不再作為 WorldTerm 連接，之後改接地點／地圖。
3. 新增 settings store 模型 `PowerMember`，保存穩定 UUID、`bookID`、`powerID`、`characterID`、手寫職稱、排序與建立／更新時間。
4. `PowerMember` 只以角色 UUID 指向主 store，不建立跨 store SwiftData relationship，也不複製角色名稱。
5. 同一 `powerID + characterID` 只允許一筆成員資料，由 Store 操作驗證；職稱修改更新原資料。
6. V4→V5 採可安全遷移的新增欄位／模型；既有勢力 UUID、文字欄位、層級與隸屬完整保留，新連接為空，不猜測宗教、政治或名單文字。

### Store 操作與關係規則

1. `V5SettingsStore` 集中提供世界條目連接／清除、成員新增／改職稱／移除，以及指定方向的直屬上級解除操作。
2. 保留現有候選方向、跨級、多上級與衝突阻止邏輯；移除畫面上的新增下級入口，但不刪除既有下級關係或改變底層圖模型。
3. 將目前不分方向的 `removeRelations(between:and:)` 改為只刪除指定 `lowerPowerID → upperPowerID` 的操作，避免誤刪反向資料。
4. 刪除勢力時一併刪除該勢力的成員資料與所有直接隸屬連線；不刪除角色或世界條目。
5. 刪除世界條目前，清除四個欄位中指向該 UUID 的連接，再刪除條目並保存。
6. 刪除整本書時，將 `PowerMember` 納入既有 settings store 整書清理。

### 角色跨 store 清理與修復

1. 擴充角色刪除流程：主 store 成功刪除角色後，由 `CrossStoreDeletionCoordinator` 要求 settings store 移除該角色的所有 `PowerMember`。
2. settings 清理失敗不回滾已成功的主 store 刪除；回報 deferred cleanup error，並允許後續冪等修復。
3. 啟動或進入相關資料域時，以主 store 現存 Book／Character UUID 清除孤立成員；同時清除不存在或跨書的勢力、世界條目連接。
4. 不在主 store 角色模型新增 settings relationship，不升級主 store schema。

### UI 修改

1. 沿用現有 `PowerDetailView`，保留名稱、簡介、既有文字資料與層級管理。
2. 將關係區改為一個「選擇直屬上級」新增入口、可解除的直屬上級列表，以及唯讀的直屬下級列表；完全移除新增下級入口。
3. 直屬上級候選只取同書較高層級勢力，排除自己、未分級、方向錯誤及已存在的直屬上級；候選清楚顯示名稱與層級。
4. 宗教、政體提供同書且相同分類的世界條目單選與清除；核心與範圍顯示未來地點／地圖連接提示，不提供 WorldTerm 選擇。
5. 成員區提供角色單選、職稱輸入與新增；既有成員可修改職稱或移除，已加入角色不再列入候選。
6. 空資料、無候選、來源已失效與保存失敗都使用明確狀態；不以不存在的名稱副本掩蓋失效連接。

### 測試與驗證

1. 遷移：V4 檔案型 settings store 升級至 V5，驗證勢力 UUID、全部舊文字、層級、隸屬、地點及世界條目不變，新欄位為空。
2. 世界條目連接：宗教／政體各自保存、重新開啟、同書與分類限制、重新命名顯示、清除，以及刪除條目後解除連接；核心／範圍維持未啟用提示。
3. 成員：新增、修改職稱、移除、同勢力角色唯一、同角色可加入不同勢力、跨書拒絕、角色重新命名及檔案重開。
4. 刪除：勢力刪除清成員與連線；角色刪除清成員；整書刪除清全部 V5 settings；附屬清理失敗可重試且不恢復已刪主資料。
5. 關係：只有直屬上級候選、跨級與多上級保留、上級解除只刪指定連線、下級列表正確投影、層級衝突仍阻止。
6. 修復：孤立角色、勢力、世界條目與跨書 UUID 連接可冪等清理，不修改有效資料。
7. UI 冒煙：未分級、無上級候選、新增／解除上級、唯讀下級、四個世界條目欄位、成員與職稱、錯誤提示及既有文字保留。
8. 完整回歸：V5 settings 專項、全部 XCTest、Debug test、無簽章 Release build、frontend parse 與 `git diff --check`。

### 主要風險與回復

- 角色成員跨越主 store 與 settings store，無共同 transaction；採主資料優先、附屬清理可重試與啟動修復。
- 舊宗教、政治與名單是自由文字，禁止自動解析；若新版功能需回復，可停止使用新連接而不改寫舊文字。
- 世界條目與勢力雖在同一 store，仍用 UUID 以配合既有 settings 模型；所有刪除與修復規則由 Store 集中處理。
- 若實作發現必須改變已確認資料語意或 UI，停止並退回相應批准點。
