# V9.2e 勢力關係重複檢查錯誤傳遞

> 狀態：closed（兩個重複檢查已傳遞查詢錯誤）
>
> 工作單位：避免兩個會寫入勢力關係的操作把重要查詢失敗視為沒有重複資料。

## 目標與完成條件

- `V5SettingsStore.addSuccession` 與 `addPowerRelation` 的既有重複檢查，將 `try? context.fetch(...) ?? []` 改為 `try context.fetch(...)`；查詢成功時保持原過濾、重複判斷、插入、保存與回傳流程。
- 兩個 API 原本即為 `throws`，既有 View 呼叫端已有 `catch` 並顯示 `errorMessage`；不新增 UI 或修改文字。
- 查詢失敗時不再走到插入；底層錯誤交由原錯誤出口顯示。資料 schema、關係定義和正常輸入行為不變。
- 靜態核對兩處 `try?` 已移除、呼叫端仍 catch；通過差異檢查及主機 Debug build。故障注入與 GUI 未授權執行，仍列入後續驗收。
