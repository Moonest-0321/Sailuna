# 完結作品恢復連載與唯讀閱覽

> 整體狀態：active
>
> 目前階段：功能已接入並通過專項 XCTest、語法與差異檢查；隔離資料 GUI 驗收待完成。

## 工作單元

- **目標**：完結作品可恢復為連載；完結期間可閱覽但同書全部資料不可修改。
- **完成條件**：完結列提供恢復連載；完結作品所有同書寫入入口受限制而閱讀／導覽正常；恢復連載後所有同書編輯恢復；狀態重啟後保留。
- **範圍**：發布狀態操作、書籍總覽與編輯器、設定集、地圖、故事規劃、時間軸、每書 AI 對話及其他依書 UUID 保存的資料。
- **非目標**：不改 SwiftData schema、備份格式、全書刪除流程、新書匯入流程及全域應用程式設定。全域備份還原仍依既有明確流程執行；此 I 提案把唯讀門檻限定於書籍工作區的互動寫入，若使用者希望全域還原也拒絕覆寫完結書，須另調整範圍。

## 現況

- `BookPublicationStore.advance` 目前只允許草稿→發布中→完結，完結後不再提供狀態操作。
- 發布列表對草稿顯示「發布」、發布中顯示「完結」；完結列只有狀態文字。書櫃 ongoing 分區已稱「連載」。
- 書籍狀態保存於 `Sailune/Publication Status.json`；`Book.status` 是 transient，不適合作為唯讀權限來源。
- 完結作品從書櫃及總覽仍可開啟目前可編輯的工作區。
- 書籍資料跨主 store、設定 store、物品副本 store、能力進度 store、故事規劃 store、封面檔與每書 AI 對話 JSON。部分畫面在讀取時會執行 `ensureDefaults`／`ensureProfile`／`ensureAnnotation`／`ensureDefaultMap`，唯讀路徑必須避免因此寫入。

## R 決策

- 狀態流程為草稿→連載→完結→可選恢復連載；發布列表 ongoing 顯示「連載」。
- 完結作品可開啟及瀏覽，但同書全部資料唯讀，包含書名／簡介、封面、卷節結構、節標題及正文、角色／物品／能力／勢力及其關聯、時間軸、地圖、故事背景／規劃、設定集目錄及每書 AI 對話。
- 發布頁完結列提供「恢復連載」；成功後即恢復可編輯狀態。狀態仍由既有 sidecar 保存，無 schema 變更。
- 使用者於 2026-09-26 回覆「R」並選擇「全部同書資料唯讀（建議）」。R approved。

## U 決策

- 發布頁完結列顯示「完結」與「恢復連載」按鈕；按下後立即改回「連載」。
- 從書櫃或既有入口開啟完結作品時沿用現有工作區版面；正文與同書資料保持可閱覽，新增、修改、刪除、排序及關聯操作停用。
- 瀏覽、搜尋定位、節次導覽、選取／複製、地圖平移縮放與不寫回書籍資料的匯出仍可使用。
- 使用者於 2026-09-26 回覆「U」，批准上述流程及文字線框。U approved。

## I 實作計畫（approved）

### 影響範圍與接線

1. **狀態來源與恢復 action**：`Sailune/Book.swift` 的 `BookPublicationStore` 新增只接受 `.completed` 的恢復 action；先原子保存狀態 sidecar，成功後才更新 observable 狀態，失敗時保持完結。`Sailune/HomeFeatureViews.swift` 的發布列接入「恢復連載」；發布列表 ongoing 文案由「發布中」統一為「連載」，沿用共用文案／無障礙來源。
2. **每書編輯權限投影**：新增純值 access policy，從 `BookPublicationStore.status(for:)` 得出書籍是否唯讀；不使用 `Book.status` transient 欄位。`ContentView`／`BookOverviewView`／`EditorWorkspaceView` 以同一書 UUID 注入可觀察權限，狀態恢復時即時解除唯讀；不同書籍隔離。
3. **書籍總覽及正文**：`BookOverviewView.swift`、`EditorWorkspaceView.swift`、`RichEditorView.swift`、`SearchReplaceView.swift` 停用書名／簡介／封面、卷節新增／改名／刪除／排序、正文輸入／取代、正文附帶 tag／大綱建立等寫入。AppKit `NSTextView` 設為不可編輯但保留選取、複製、捲動與導覽；搜尋保留，取代停用。
4. **設定集與同書關聯**：盤點並接入 `InspectorViews.swift`、`CharacterInspectorViews.swift`、`ItemInspectorViews.swift`、`AbilityInspectorViews.swift`、`PowerSettingViews.swift`、`PlaceWorldTermViews.swift`、`RelationshipWorkspaceViews.swift`、`SidebarSettingsManagerView.swift`；角色、物品副本／歷史、能力進度、勢力、地點、世界條目、關係與設定集目錄皆可讀但不能寫。相關底層入口包括 `V5SettingsStore`、`PowerHierarchyStore`、`ItemCopyStore`、`AbilityProgressStore`。
5. **地圖、時間軸與故事規劃**：`MapViews.swift`、`MapManagementViews.swift`、`OutlineViews.swift`、`TimelineViews.swift`、`TimelineEraManagementViews.swift` 接入相同權限。標記、背景版本、地圖、事件／節點、年號、故事背景、故事線／階段／規劃項目及正文錨點均禁止寫入；只讀載入不得呼叫會建立資料的 ensure action。
6. **每書 AI 對話與其他 sidecar**：`SailuneAIChatSidebarView.swift`、`SailuneAIChatViewModel.swift` 在唯讀狀態保留既有對話檢視，不送新訊息、不建立／刪除／改名對話；發布數據頁只讀，不受影響。封面檔唯讀載入仍可用，儲存／移除須停用。
7. **規格與測試**：更新 `docs/spec-editor.md`、對應發布規格／驗收、`docs/architecture.md`、`docs/project-status.md` 及本工作單；因不改 schema／備份格式，不改遷移或一致性政策，除非盤點發現實際資料關係改變。

### 相容性與不變條件

- 沿用既有 publication sidecar 與缺省 `.draft` 行為；不改 V5 schema、既有 sidecar 編碼或舊備份相容性。
- `.completed` 恢復 `.ongoing` 是唯一新增的反向狀態操作；status 寫入失敗時不切換畫面權限。
- 只讀權限按 book UUID 計算，不能影響其他草稿／連載作品。狀態為觀察來源，切換狀態時既有工作區應即時更新。
- 全域備份還原、整本刪除與新書匯入依既有 App 級流程，唯讀政策不攔截；這是本提案的範圍邊界。

### 工作拆解與風險

1. 新增並測試 completed→ongoing 持久化 action 與 access policy。
2. 接通發布列表按鈕、狀態文案、錯誤回饋及 accessibility label。
3. 先接總覽／正文，處理 NSTextView 編輯、取代、鍵盤／右鍵與待存文字。
4. 逐模組接設定集、地圖、時間軸、大綱與每書 AI 對話；逐項核對新增、修改、刪除、排序、拖曳、綁定、shortcut 和 context menu。
5. 移除唯讀路徑的 ensure 寫入；測試既有資料與缺少可選資料時皆可唯讀顯示。
6. 更新產品規格、驗收與工作交接。

- **主要風險**：寫入由 SwiftData binding、各 Store action、AppKit editor、手勢、鍵盤命令及讀取時補建分散觸發；只停用可見按鈕不足以保證唯讀。需同時封鎖回呼／命令入口，保留必要瀏覽互動。
- **待驗邊界**：同書工作區以外的全域備份還原仍能整體替換資料；整本刪除維持獨立現行操作。若這與「全部同書資料唯讀」的預期不同，需在 I 批准前修訂。
- **資料狀態風險**：其他視窗若在完結狀態切換前仍有未提交的正文暫存，需確認 flush 時序；完成狀態變更不能丟失已輸入文字，也不能在完結後再接受編輯。

### 驗收計畫

- Store／純值測試：草稿→連載→完結及完結→連載；儲存成功後狀態重開保留；寫入失敗時狀態及權限不變；兩本書隔離。
- 同書唯讀檢查：透過書櫃、尋找及書籍總覽開啟完結作品；正文與所有同書資料可檢視／導航，但新增、改名、編輯、刪除、排序、拖曳、關聯、取代及 AI 送出不能造成變更；缺少選用 profile／annotation/map 時唯讀開啟不得補建。
- 恢復檢查：發布頁按「恢復連載」即時更新標示及已開工作區權限；重開後仍可編輯。已保存內容、關聯與 sidecar 完整保留。
- 回歸：草稿及連載作品的既有編輯功能不變；閱讀時節次導覽、搜尋、選取／複製、地圖平移縮放與匯出可用。
- UI 人工驗收：書籍總覽、正文、設定集、地圖、時間軸、大綱皆抽查滑鼠、鍵盤 shortcut、context menu、disabled/accessibility 描述與 Light／Dark；以隔離資料執行，不操作正式作者資料。
