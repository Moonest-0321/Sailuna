# UI／UX 原則

## 核心原則

### 低干擾

作者應能在不開啟設定集、不填寫完整資料的情況下完成正文寫作。提示與輔助資訊應在需要時出現，不阻塞主要輸入流程。

### 漸進式建立

設定可以在正文創作過程中逐步補上。系統可提示可能的角色、物品或引用，但不應強迫作者在第一次遇到名稱時完成全部欄位。

### 關聯可見

正文、設定集、時間軸與歷史資料之間應能快速雙向跳轉，讓作者能用最少操作確認故事脈絡。

### 允許不完整

未完成的設定應可先保存，並以清楚的待補提示、標籤或註記保留線索；空白不應被系統擅自解讀成錯誤或虛構內容。

### 自動保存與可恢復

一般輸入不應要求作者手動按保存。儲存狀態需可見；失敗時提供可理解的提示與後續處理方式。

### 一致且可預期

相同類型的資料應使用相似的新增、編輯、刪除、排序與確認流程。破壞性操作要明確說明影響範圍。

### 以現況為設計起點

任何涉及既有畫面或互動的 UI 提案前，必須先實際檢視目前 app 的對應畫面、空白／已有資料狀態與可用操作；程式閱讀只能補足資料與行為，不能取代實際畫面檢視。提案應明確說明哪些既有資訊層級與操作被保留、調整或移除，避免憑想像另造不相容的介面。

### 文字編輯優先

帆夢即使不使用設定集，也應是一個完整、穩定、易用的文字編輯器。設定功能不能降低正文輸入的速度與可靠性。

### 面向大型敘事

介面需考慮大量角色、長篇正文、多條時間軸與複雜關係；搜尋、篩選、排序與分層檢視比裝飾性功能優先。

## 互動規則

- 使用者主動選擇的設定優先於系統推測。
- 名稱辨識有歧義時，提示並交由作者確認，不自動建立錯誤連結。
- 從正文跳至設定集後，應保留返回正文與原位置的路徑。
- 長時間或高成本操作需提供進度／載入狀態。
- 錯誤訊息要說明發生什麼、資料是否安全、下一步能做什麼。
- 相同語意的操作在不同畫面使用同一圖標、顯示文字與 accessibility label；不同上下文需要例外時，語意資源清單需記錄例外及原因。
- 一般表單底部主要操作位於右側（trailing），取消緊鄰主要操作之前；破壞性操作獨立成組，不與主要確認混成同等強度的一列。整個流程只呈現一個主要操作。
- 純圖標按鈕須可辨識且有 accessibility label；tooltip 補足圖標的操作意思。破壞性動作不可只靠紅色或圖標暗示，須提供明確動作標籤及適當的確認／復原方式。
- 純圖標工具列按鈕以至少 28 × 28 pt 互動範圍作為 V9 試行基準。互動範圍不可互相重疊或越過控制項所屬區域；實際操作需以滑鼠／觸控板及鍵盤驗收。
- 欄位須有可見名稱或 VoiceOver 可讀名稱；placeholder 僅作輸入提示，不能代替欄位名稱。錯誤訊息放在欄位附近並指出可採取的修正。
- 欄位首行文字、placeholder、游標與選取內容必須完整顯示在邊框內，並與圓角保持可讀間距；文字不得貼穿描邊、被圓角裁切，或與欄位名稱重疊。單行與多行欄位分別依平台文字 inset／共用編輯器 inset 驗收，不以拉高欄位或逐畫面加 offset 遮掩問題。
- 點擊、拖曳、平移、縮放或 hover 共存時，需明確指定互動區、事件接收者與衝突時的操作結果；透明裝飾層不能攔截操作，遮罩則須阻擋背景穿透。
- 元件尺寸與間距沿用共用 UI 規範的語意 token；位置依父容器可用空間排版，不以固定 offset 模擬跨區定位。
- UI 設計開始前，先以實際 app 檢視建立目前畫面的基線；若因環境無法檢視，必須明確標示限制並取得使用者提供的畫面或方向，不得將推測當成現況。

## 不應做的事

- 不因設定未完成而阻止正文寫作。
- 不在未確認下批次改寫正文或刪除設定。
- 不把暫時的 UI 提示當成永久產品規則。
- 不為了顯示更多資訊而讓主要寫作區域失去焦點。

## 後續 UI 守則收集重點

- 任何輸入框在彈窗中按 Enter，應立即確認並收起彈窗。
- 任何彈窗都可點擊空白區域取消。
- 列表中的可點擊項目，整行都可點擊進入；若項目支援直接修改，點擊文字區域進入修改，其餘區域點擊進入項目。
- 純文字按鈕的整個文字矩形區域都必須可點擊生效，不可只有文字筆畫範圍可點擊。
- 同行內容必須對齊，包含符號與文字。
- 不加入多餘的說明文字。
