# V9.1x 欄位首行與圓角安全內距稽核

> 狀態：active
>
> 工作類型：依使用者明確要求納入 V9 的共用欄位規則與程式盤點；本切片先建立驗收規格並稽核候選，不擅自改動尚未證實有問題的畫面。

## 目標

避免 TextField／TextEditor 的首行文字、placeholder、游標或選取內容被圓角、描邊、padding、frame、clip 或 overlay 擠壓、裁切或覆蓋，統一欄位文字 inset 的責任並找出需要後續修正的具體呼叫點。

## 範圍

- 盤點 `SailuneFormTextField`、`SailuneSearchField`、`InsetTextEditor`、`SailuneBorderedTextEditor` 及其直接呼叫端的文字 inset、font、frame、clip、背景與描邊順序。
- 以可見文字區域為準核對單行與多行欄位，不將原生 TextField 與 TextEditor 假設成相同內距。
- 對確認有視覺缺陷且有可重現畫面的呼叫點，另建實作切片或依已批准的精確修正範圍處理；共用元件內的修正須檢查所有已接入呼叫點。

## 非目標

- 不改欄位文案、Binding、保存時機、提交鍵、驗證、組字、選取或 Undo 語意。
- 不以固定增加高度、外層 offset、改圓角／描邊色或剪裁文字作為通用修補。
- 不將使用者提供的 `AppearanceRow` 截圖當成已證實文字穿模的證據；該圖沒有呈現此缺陷。

## 已決定

- 工程與 UX 規則要求文字繪製區完整位於描邊／圓角內；圓角不得裁切文字、placeholder、游標或選取。
- 單行欄位沿用平台控制項 inset；多行編輯器的 inset、內距與最小高度由共用 variant 負責，呼叫端不得猜原生預設值。
- 驗收涵蓋首行繁體中文字形、placeholder、捲動起點、focus／游標／選取，以及 Light／Dark；組字與 Undo 不回歸。

## 暫時假設與證據限制

- `InsetTextEditor` 目前明確使用水平 9 pt、垂直 8 pt padding，再設定背景、圓角 clip 與描邊。
- `SailuneBorderedTextEditor` 目前只有最小高度與圓角描邊，沿用原生 TextEditor 內距；尚無文字穿模的指定畫面或重現步驟，因此不能判定該元件或任一呼叫點已故障。
- 共用單行欄位目前使用平台 `.roundedBorder`；不可僅憑其外層沒有自訂 padding 推論所有原生邊界情況。

## 驗收條件

1. 以程式盤點列出所有共用 editor variants 及其呼叫點，確認 modifier 順序與其 inset 所有者。
2. 可見文字、placeholder、游標與選取均不接觸／穿過圓角描邊，也不與 label 重疊；首行與首字有穩定、可讀的內側留白。
3. 從欄位起點輸入含高低筆畫繁體中文字，並檢查空欄、捲動、focus、選取、組字、Undo 及 Light／Dark。
4. 若需修改共用 inset，對所有已接入該 variant 的代表性呼叫點逐一核對；任何無法由現有畫面確認的情境標為未驗收，不宣稱完成。

## 批准狀態

- R：使用者明確要求 V9 需處理此問題；本切片的規則與盤點範圍已授權。
- U：本切片只補充欄位內距規則並作唯讀候選稽核，不變更畫面外觀，記為 `not_applicable`。任何要改變特定畫面 inset／高度／外觀的修正，須依具體證據提出該畫面的 UI 範圍。
- I：本切片不授權未證實缺陷的 UI 程式修改；如稽核確認可重現問題，另列精確修改、影響呼叫點與驗收步驟後再開始。

## 目前盤點

- `InsetTextEditor` 與 `SailuneBorderedTextEditor` 的內距責任不同，需維持用途區別並在後續畫面驗收其可讀安全區。
- 靜態呼叫點盤點：`InsetTextEditor` 六處，位於 `CharacterInspectorViews.swift` 兩處、`ItemInspectorViews.swift` 兩處、`CharacterHistoryViews.swift` 一處、`CharacterSectionViews.swift` 一處（V9.2ag／2ai 僅搬移 View，編輯器配置未變）；`SailuneBorderedTextEditor` 六處，其中四處位於 `PowerSettingViews.swift`、兩處位於 `PlaceWorldTermViews.swift`（V9.2ac／2ad 僅搬移 View，編輯器配置未變）。這只記錄採用範圍，不代表每一處都有故障。
- 共用單行欄位目前接入 37 處（V9.1ag 新增筆名、物品副本名稱與勢力職稱四處；V9.1ai 新增能力詳情五處；V9.1aj 新增物品相關六處；V9.1ak 新增書籍與故事線五處），另有搜尋欄位七處；其 `.roundedBorder` 與搜尋框圓角分別由平台控制項及 HStack 背景承擔。遇到首行被裁切的單行欄仍須查該畫面自己的外層 modifier／容器。
- 另有五個原生 `TextEditor` 程式呼叫點未經共用 editor wrapper：`EditorWorkspaceView.swift` 章節註記一處、`OutlineViews.swift` 故事背景直接欄一處及供五個欄位共用的 builder 一處、`ContentView.swift` 筆名檔案簡介一處、`AuthorSettingsView.swift` 個人簡介一處。這些欄位各自組合 padding、rounded background／border 與 placeholder overlay；尤其 placeholder 的手動 padding 必須與 TextEditor 實際首行 inset 對齊，列為第二批候選核對，不能假設已由兩個 wrapper 覆蓋。
- `CompositionAwareTextField` 是角色名稱專用 AppKit 控制，`textContainerInset` 與 `lineFragmentPadding` 設為 zero，父層最小高度 32 pt、字體 22 pt；它沒有圓角框，但屬於需單獨確認文字 baseline／垂直裁切的自訂輸入例外，不可機械改用一般 `TextField`。
- 靜態優先核對的邊界組合：`SailuneBorderedTextEditor` 六處僅有 `frame(minHeight:)` 與圓角描邊；`ContentView` 筆名簡介及 `AuthorSettingsView` 個人簡介只在原生 `TextEditor` 外疊圓角邊線，其中後者 placeholder 另設 8 pt padding；`EditorWorkspaceView` 章節註記使用 6 pt editor 外距及獨立 11 pt placeholder 外距。這些是首行／placeholder inset 不一致的候選，仍需實際畫面確認是否穿模。
- 本輪使用者截圖只用於 `AppearanceRow` 排列與刪除按鈕基線，不包含文字編輯器穿模現象。
- 2026-09-24 在執行中 Sailune 的書籍總覽「故事背景」彈窗，以未保存的繁體中文首行檢查「世界／時代背景」原生編輯欄：深色外觀中首行位於圓角範圍內，沒有重現穿模。關閉彈窗後總覽仍顯示背景未設定；此證據只覆蓋該單一欄位、深色、首行，不代表其他欄位已驗收。
- 2026-09-24 在執行中的角色「安東」服裝外觀列，直接觀察既有「新外觀」首行位於 `InsetTextEditor` 的深色圓角描述框內，沒有重現穿模；未輸入新文字、切換類型或保存正式資料。這只覆蓋另一個欄位的既有首行，不能取代使用者所指問題欄位的重現畫面。
- 2026-09-25 使用者提供地點「簡介」首行截圖：`PlaceDetailView` 的 `SailuneBorderedTextEditor` 中「你好」幾乎碰到圓角框上邊線。該 wrapper 目前無明確內容內距，已建立 [V9.1am 精確 UI 提案](v9.1am-bordered-editor-first-line-inset.md)；這是目前首個由使用者畫面支持的具體穿模候選，不推論其他欄位已故障。
