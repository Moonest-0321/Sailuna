# V10.2 發布書籍數據頁

> 狀態：R／U／I approved；實作及專項自動驗證完成，隔離 GUI 冒煙部分完成，數據頁進入後的 CUA 回讀受原生連線中斷阻擋。
>
> 工作單位：從發布頁選取書籍後，開啟該書的創作者／讀者數據頁。

## 目標

在發布頁選取一本書後進入該書數據頁，呈現創作者編輯字數與讀者數據。尚未取得的數值維持空白，不以估算或虛構值補上。

## 現況查核

- 發布頁目前由 `StartPublishingView` 顯示所有書籍；每列有書名、目前狀態與獨立的「發布／完結」狀態操作。點擊書名目前沒有導覽行為。
- `Book` 保存書名等基本資料及 `createdAt`／`updatedAt`；`Section` 保存目前正文、字數及 `updatedAt`。編輯器保存時會更新節與書的最後修改時間，但沒有每日編輯事件或歷史字數變化。
- `BookPublicationStore` 只保存草稿／發布中／完結狀態。專案沒有接入發布平台、閱讀量、書櫃持有人、追更或收益資料來源。
- 因此目前不能回算歷史每日編輯字數；讀者五項數據均無資料來源。不能把更新日當作實際編輯量，也不能以目前正文總字數冒充每日編輯量。

## 使用者提出的需求

從發布頁點擊一本書後進入新的頁面，內容包括：

1. **創作者**
   - 今日編輯字數。
   - 近一週每日編輯字數折線圖。
2. **讀者**
   - 今日閱讀數。
   - 近一週每日閱讀數折線圖。
   - 近一週每日加入書櫃讀者數折線圖；數值按「保有量＝持有＋新增－離開」計算。
   - 近一週每日追更率折線圖；使用「閱讀至最後一節的讀者數 ÷ 加入書櫃讀者數」計算。
   - 近一週每日收益折線圖。
3. 無法取得的數據留白，不用推測值代替。

## 已確認需求細節

- 使用者確認點擊書名進入該書數據頁；「發布／完結」維持獨立狀態操作。
- 創作者每日編輯字數採「淨變化」，即當日保存正文的字數增加減去刪除；淨變化可以是負數。

## 已核准範圍與日期定義

- 每日及近一週依裝置本地時區切分；「近一週」為今天加前六個日曆日。
- 每日編輯字數只從功能開始記錄後取得；沒有歷史基線的日期留白。具體基線保存策略留待 I 盤點。
- 指標區及圖表位置仍呈現；沒有來源的值及線圖資料留白，不顯示虛構的 0。空圖表狀態的具體呈現留待 U 確認。
- 本版不新增發布平台連線、讀者追蹤或收益擷取，也不提供作者手動填造數據；讀者數據若無可用來源就留白。
- 不決定資料檔、schema 或遷移策略，留待 I 盤點。

## 非目標（暫定）

- 不代作者向外部平台發布作品。
- 不在沒有來源時推算閱讀、持有人、追更或收益數字。
- 不把現有正文總字數或最後修改時間當作每日編輯量。
- 不修改書籍正文、發布狀態語意或既有作者資料。

## 驗收條件草案

- 從發布頁選取書籍可進入該書專屬數據頁，且不會把不同書籍的數據混在一起。
- 數據頁包含上述創作者與讀者指標，圖表日期範圍及日序明確。
- 有可用數值時按核准口徑呈現；沒有來源或資料時保持空白，不產生假數值。
- 編輯字數按當日成功保存的正文字數淨變化計算；刪除多於新增時允許顯示負數；無歷史記錄的日期留白。
- 既有草稿→發布中→完結操作仍可正常使用。
- 每日編輯數據僅歸屬目前書籍，不混入其他書籍；時區與七日區間依 R／U 最終決定。

## R 批准記錄

- 使用者於 2026-09-26 回覆「R」，核准上述需求及範圍。
- 使用者確認每日編輯字數採淨變化；點擊書名進數據頁，狀態操作獨立。
- 核准的近一週區間為裝置本地時區的今天加前六個日曆日。

### 資訊架構與流程

1. 在「發布」列表點擊書名，進入該書的數據頁；點擊同列「發布／完結」仍只推進發布狀態。
2. 數據頁頂部提供「返回發布」及目前書名；返回後回到發布列表。
3. 主內容依序分為「創作者」與「讀者」兩區，保持使用者提出的閱讀順序。
4. 「創作者」先顯示今日編輯字數，再顯示近一週每日編輯字數折線圖。
5. 「讀者」先顯示今日閱讀數，再按需求順序放置四張折線圖：每日閱讀數、每日保有書櫃讀者數、每日追更率、每日收益。
6. 數據頁內容超出視窗高度時使用主內容區垂直捲動；不新增其他書籍操作或手動資料輸入。

## I 實作與驗證計畫（已核准）

### 影響範圍

- 發布頁／路由：在 `HomeFeatureViews.swift` 的 `StartPublishingView` 增加選取書籍的頁面狀態與數據頁；沿用根頁既有側邊欄，書名按鈕只進入數據頁，「發布／完結」仍呼叫原有狀態 action。返回回到發布列表。
- 數據顯示：新增書籍數據頁與小型可重用圖表呈現，使用系統 Swift Charts；只傳入按本地日排列的可選數值。日期軸仍有七日；空值不畫點、不補零。負數編輯淨變化須可視辨認。
- 每日編輯資料：新增 `BookWritingStatsStore`（名稱可依現有命名調整）及獨立 JSON sidecar，依 `bookID`、裝置本地日保存成功正文編輯的有號淨字數累計。沿用 `RichEditorView.swift` 現有非空白字元計數語意；只在正文保存成功後記錄前後差額。今日／圖表只呈現已有成功記錄的日子，包含記錄結果為 0 的日子；功能啟用前歷史留白。讀者指標目前沒有來源，維持 nil／空白，不造資料或新增外部平台串接。
- 編輯入口盤點：記錄事件接在編輯器正文保存；另檢查 `SearchReplaceView.swift` 這類作者明確改寫正文的入口，讓其成功保存時也記錄淨差額。自動引用同步、資料修復、匯入與刪除不先算作「每日編輯」；若需求希望涵蓋它們，須先修訂定義。這是目前的實作假設。
- 資料相容／生命週期：在 `SailuneDataLocations` 增加與發布狀態分離的 `Sailune/Writing Stats.json`；注入專責 Store。主 `NovelWriterSchemaV5` 不變。備份／還原納入可選 `writing-stats.json`，保留舊備份可還原的相容性；新備份做 checksum 驗證。還原 rollback 需一併保存／回復 sidecar；書籍永久刪除時按 bookID 清理。若正文 SwiftData 保存成功但 sidecar 記錄失敗，正文不回滾、不假稱共同原子；記錄錯誤供診斷，該次統計不可顯示為已知數值。
- 文件：新增 V10.2 對應規格／驗收條件；更新 `docs/backup-and-migration.md`、`docs/consistency-audit.md`（若檢查後確認內容需調整）、`docs/project-status.md`、本工作單及交接。

### 工作拆解

1. 依上述明確作者正文編輯範圍實作 sidecar Store：本地日鍵、書籍隔離、有號累計、原子 JSON 寫入、讀取／重開、書籍清理及錯誤回報；不新增主 schema。
2. 由正文編輯保存流程把舊／新字數差額交給 Store；確保防抖保存與結束編輯 flush 不重複記錄，失敗保存不入帳。接通作者明確搜尋取代路徑。
3. 實作核准的發布列表進入／返回流程及數據頁。今日與七日本地日期投影區分 nil、有效 0 與負值；讀者五個指標目前投影為 nil。
4. 整合備份、還原 rollback 與刪書清理，處理沒有此 sidecar 的舊備份；檢查現有跨 Store 刪除流程與錯誤回報。
5. 更新規格、工作狀態、交接，保留其他工作與使用者原有修改。

### 資料相容性及風險

- 此資料自功能可用後才開始收集，無法從 `Section.updatedAt` 或當前正文回算舊日期；舊日期留白。JSON 損壞／不可寫時不合成 0；錯誤需由 Store 回報並留下可診斷狀態。
- 編輯正文與 sidecar 是兩次不同儲存，沒有共同交易。順序採正文先成功保存，再追加統計；若 sidecar 寫入失敗，正文仍保留，當次執行將受影響書籍的統計標示不可用並記錄錯誤，不把缺失顯示成 0。若程式在錯誤後立即結束，sidecar 無法持久記下失敗旗標，重開後可能無法辨識該次少記；此限制須明確留在規格，且以測試覆蓋可模擬的錯誤路徑。
- 每日依運行時裝置本地日界線歸檔；跨時區後既有日鍵不重排，後續事件使用新的本地日期。日期投影由目前 Calendar 產生本地今日加前六日。
- 讀者數據仍沒有資料提供者；標題、日期軸／空白圖表骨架顯示，但數值全部留空。任何平台串接另列需求，不在本工作自行增加。
- 本工作不變更 V5 schema、不新增手動編輯 reader 數據、不推算 reader 數據、不改發布狀態語意，也不計數據修復或書籍匯入／刪除造成的字數差。

### 驗收與測試計畫

- Store 測試：同書同日正負差額累計、淨額為零、跨本地日期與跨書隔離、重開保存、書籍清除、日期區間投影、JSON 寫入／讀取失敗不變成 0。
- 編輯整合測試：成功保存後只入帳一次；防抖保存後結束 flush 不重複；SwiftData 保存失敗不入帳；搜尋取代成功記錄差額；Sidecar 失敗時正文仍保存且統計呈缺值。
- 備份／刪除測試：sidecar 備份及還原 round-trip；舊備份沒有統計 sidecar 可還原並清除當前統計檔；書籍刪除清理該書記錄且不影響其他書。
- UI／圖表驗收：書名進數據頁、返回發布頁、同列狀態按鈕獨立；本地七日期序、已知 0／正／負值呈現、nil 留白且沒有假點線；讀者區指標和圖表保持空白。
- 專案驗證結果：新增 Store 測試 4 項；專項 XCTest 6 項通過（4 項統計 Store、完整備份 round-trip、舊備份清除統計），無簽章 Debug build、受影響 Swift frontend parse 與 `git diff --check` 通過。測試 build 有既存 `V5SettingsTests` 不必要 `try` 警告，與本次檔案無關。
- 隔離 GUI 結果：以複製且更換 bundle ID 的 Debug App、`SAILUNE_TEST_STORE_URL` 指向 `/private/tmp/SailuneV102Smoke/Isolated.store`。成功建立隔離測試書籍、返回書櫃並打開發布列表；AX 樹確認書名按鈕與獨立發布按鈕。點擊書名後 CUA 回報「Sky Computer Use native pipe closed before response」；重讀、重設 CUA runtime 後仍不能取回數據頁，因此頁面實際呈現及返回流程未經 GUI 確認；全程沒有操作正式書籍。
- 尚未驗證：RichEditor 防抖／flush 的端到端 GUI 計數，以及編輯器 SwiftData 保存失敗故障注入；程式路徑已編譯，Store 與備份行為已有自動測試。
