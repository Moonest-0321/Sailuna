# V5.5 勢力生命週期與成員時間序

> 狀態：已實作；自動測試完成，人工 UI 冒煙待與 V5 勢力功能一併執行。
>
> 產品版本：V5.5；settings schema：`V5SettingsSchemaV9`。後續 V5.6 升級至 V10，但不改變本規格的資料語意。

## 目標

V5.5 在不改寫 V5.0 既有勢力資料的前提下，補上勢力存在狀態、生命週期事件、前身／後繼承接，以及成員加入／離開與多重職務的時間定位。時間定位沿用主 store 的 `Node` UUID，可獨立包含世界日期與正文節次。

V5.0 第一版只有勢力本身、目前直接隸屬與自由文字，不連接角色、物品、能力、地點、事件或正文。V5.2 起加入角色成員連接，V5.4 加入資源、技術、物品與能力連接，V5.5 再擴充生命週期及成員時間序；這些是後續產品版本的增量能力，不回溯改寫 V5.0 的範圍決策。

## 功能範圍

### 勢力生命週期

- `PowerUnit.existenceStatus` 保存「仍存在」、「已解散／滅亡」或「狀態不明」。
- `PowerLifecycleEvent` 逐筆保存建立、改名、分裂、合併或解散／滅亡事件，可編輯標題、說明及一個可空的 `nodeID`。
- `PowerSuccessionLink` 保存前身勢力 → 後繼勢力，可標示改名承接、分裂、合併或一般後繼，並保存說明及一個可空的 `nodeID`。

### 成員與職務

- `PowerMember` 以角色 UUID 連接同書角色，保存現任／前任，以及可空的加入、離開 Node。
- 同一角色在同一勢力最多一筆成員記錄，但可加入不同勢力。
- `PowerMemberRole` 讓一筆成員擁有多個職務；每筆保存職務名稱、是否為領導職位、現任／前任／代理／繼任／遭罷免狀態，以及可空的任職、卸任 Node。
- V8→V9 遷移會把舊 `PowerMember.title` 的非空內容回填為第一筆現任職務；空職稱不建立空白職務。

## 已確認資料語意

### 存在狀態與生命週期事件互相獨立

存在狀態是勢力目前狀態的明確欄位；生命週期事件是作者記錄的歷史。兩者不互相推導或自動同步：加入解散事件不會自動改成「已解散／滅亡」，修改目前狀態也不會自動新增事件。這可避免在事件缺日期、世界時間與正文順序不一致，或作者只完成其中一部分資料時猜測作者意圖。

### 「一般後繼」表示已建立的承接關係

V5.5 沒有預定／已完成欄位，因此 `PowerTransitionKind.succeeded` 的產品語意是作者已確認的「一般後繼」關係，不用來保存候選人、預定接任或尚未發生的計畫。若未來需要預定承接，必須另行設計狀態與轉換流程，不能從現有記錄推斷。

成員職務的「繼任」則是職務狀態標記，表示該角色以繼任身分擔任該職務；它不會自動建立勢力的前身／後繼關係。

### 前身／後繼允許多對多

同一勢力可以有多個前身或多個後繼，以表達分裂、合併及複合承接。Store 只拒絕同一本書中「相同前身、相同後繼、相同轉換類型」的完全重複記錄；不同轉換類型可分別記錄。

### 目前允許循環承接

Store 禁止勢力連向自身，但目前不阻止 A→B→A 或更長的循環。承接是作者維護的歷史語意網路，不是直接隸屬的階層圖，因此循環不會改變層級、隸屬、存在狀態或其他資料。若未來要將承接用於自動歷史推理或視覺化，再另案決定是否禁止循環。

### 時間矛盾不自動阻止或改寫

目前不比較加入與離開、任職與卸任、生命週期事件或承接 Node 的先後，也不依時間自動切換現任／前任或勢力存在狀態。理由是 Node 可只有世界日期、只有正文節次、兩者都有或兩者皆未填，未必能形成唯一全序。

因此 V5.5 允許保存表面上矛盾的組合，資料由作者判定；介面目前沒有矛盾警告。未來若增加提示，應只提示可明確比較的矛盾，不得自動覆寫作者內容。

## 刪除與來源失效語意

- 刪除成員時一併刪除該成員的全部 `PowerMemberRole`，不刪除角色。
- 刪除勢力時刪除其生命週期事件、以其為任一端點的承接、成員與職務；不刪除另一個勢力、角色或 Node。
- 刪除整本書時刪除該書的 V5 settings 資料，包括本規格新增的模型。
- 角色刪除後，由跨 store 清理移除相關 `PowerMember` 與職務；清理失敗可由後續 reconcile 冪等重試。
- Node 被刪除或不再有效時，reconcile 只把加入、離開、任職、卸任、生命週期事件與承接的 Node UUID 清空；勢力、事件標題、說明、成員、職務及狀態均保留，不猜測替代位置。
- V5 settings 與主 store 沒有共同 transaction；主資料刪除成功而附屬清理失敗時，不回滾主資料，改由後續修復收斂。

## 非目標

- 不自動由舊名推導改名事件，或由自由文字推導生命週期、承接與職務。
- 不因承接自動建立或移除直接隸屬、非隸屬關係、資產或成員。
- 不依生命週期事件自動更新存在狀態。
- 不提供預定承接、任期計算、時間矛盾阻止、關係圖或歷史模擬。
- 不複製 Node 的世界日期或正文節次到 settings store。
