# V9.1 共用 UI 試行：角色外觀列

> 狀態：active（R／U／I 已確認；共用控制接線已完成，GUI 驗收待完成）
>
> 目標切片：`CharacterSectionViews.swift` 的 `AppearanceRow`
>
> 工作單類型：既有 UI 共用元件遷移；不新增產品功能。

## R：需求與範圍

2026-09-24 補充實際畫面核對：Mac 解鎖後，以執行中的 Sailune 開啟既有角色「安東」的服裝外觀列。深色畫面顯示類型選單後緊鄰 trash 圖標，描述編輯框、場景／用途欄和時間定位順序與使用者基線一致；accessibility tree 的刪除控制名稱為「刪除外觀」。現有「新外觀」首行位於描述框內，這只涵蓋該欄的深色既有內容。沒有點擊刪除、改變類型或輸入正式作者資料；檢查後已返回書籍總覽。28 pt 實際命中、Light、身體特徵、focus／CJK 與 VoiceOver 仍未驗收。

### 目標

在單一 `AppearanceRow` 試行共用 UI 基礎，驗證按鈕、欄位、一般多行編輯器、surface token、圖標語意與 accessibility label 能否由集中實作提供，同時維持現有資料綁定與領域操作。

使用者以「可」接受 `AppearanceRow` 作為 V9.1 候選。批准範圍限於此切片的共用 UI 試行，不代表核准全域遷移或其他功能重構。

### 現況基線（程式碼與 2026-09-24 深色畫面）

- `AppearanceRow` 在 `CharacterSectionViews.swift`，一列包含類型 `Picker`、trash 圖標刪除按鈕、外觀描述 `InsetTextEditor`（`minHeight: 110`）、依外觀類型切換 placeholder 與 Binding 的單行 `TextField`，以及 `CharacterTimelinePlacementEditor`。
- 刪除以 `onDelete` closure 傳入；目前父層使用 `modelContext.delete(appearance)`。本試行不更改刪除是否確認、刪除副作用或儲存時機。
- `InsetTextEditor` 已由數個設定／歷史畫面共用；V9.1a 已將定義移至 `SharedUI/SailuneUIFoundation.swift`，現有包裝仍設定 `scrollContentBackground`、字體、padding、背景、圓角與描邊。
- 先前桌面列出 Sailune 正在執行，但 `cua.getApp("Sailune")` 讀取逾時；兩份 Sailune App 共用 `com.MooNest.Sailune` bundle ID，其中一份沒有視窗。當時的來源碼線框只能作結構基線；下方 2026-09-24 使用者截圖已補上深色畫面證據。
- 2026-09-24 再次用 `cua.getApp("Sailune")` 讀取仍逾時。來源碼進一步核對：第一列 `HStack(alignment: .top)` 只有固定寬 150 pt 的類型 Picker 與 `.plain` 刪除按鈕，兩者之間及刪除按鈕之後沒有 `Spacer`；刪除按鈕在來源碼排列上緊鄰 Picker，不能畫成已位於右緣。按鈕沒有明定 frame、tooltip 或 accessibility label，實際 hit area 尚不能由此推定。
- 使用者於 2026-09-24 提供深色模式截圖，已保存為 [`docs/assets/v9-appearance-row-dark-2026-09-24.png`](../assets/v9-appearance-row-dark-2026-09-24.png)（556 × 828 像素的局部畫面）。畫面確認「類型」選單後緊接 trash 圖標，右側仍有空間；「外觀描述」下方為大面積編輯欄，其下是「場景／用途」單行欄，時間定位列有兩個圖標。下方「新增外觀」選單正在展開，遮住下一個區塊的一部分。截圖僅為單一服裝資料與深色狀態，不能推論淺色、身體特徵、hover／focus 或可點擊框。
- `CharacterTimelinePlacementEditor` 在下方時間定位列內另有「敘事版本」與「時間序版本」兩個 `.borderless` 圖標按鈕，Image frame 各 22 × 22 pt、間距 6 pt，已有 accessibility label／help；實際 Button 命中外框仍待畫面核對，不能直接等同 Image frame。
- `docs/work-items/v9.1a-ui-foundation.md` 已完成未接入畫面的圖標、文字、色彩與尺寸基礎，並通過主機 Debug build；本試行後續可引用這些定義。

### 納入

1. 沿用 V9.1a 已移入 UI foundation 的 `InsetTextEditor`；在本列仍保留 `minHeight: 110` 及既有輸入、選取、焦點行為。若後續要改名或擴充 API，須逐一核對既有呼叫點。
2. 將此列的文字欄位接到共用單行欄位基礎；保留 outfit 顯示／編輯 `usage`、body feature 顯示／編輯 `note` 的條件和 Binding。
3. 將刪除控制接到共用 destructive／toolbar 語意按鈕與集中圖標 key；保留目前位置、事件 closure 與刪除確認行為。
4. 將此外觀列與編輯器的背景、邊線等映射至核定的語意 theme token；不更動 map canvas 等其他功能區。
5. 為純圖標刪除按鈕提供一致的 tooltip／accessibility label，例如「刪除外觀」。最終文字需與 V9 語意資源表一致。

### 明確不納入

- 不改外觀列排序、類型選項、資料模型、日期／時間定位、保存／自動保存或刪除語意。
- 不加入新的刪除 confirmation、不移動類型 Picker、不重排整列、不改產品文案意圖。
- 不遷移其他 `AppearanceRow` 以外呼叫點；若共用元件 API 需要由其他畫面一起搬遷，先停止並提出範圍變更。
- 不把正文 `NSTextView`、AI composer 或 Timeline placement editor 改成一般文字編輯器。

### R 驗收條件

- 共用元件承接本列按鈕、欄位、一般文字編輯器、顏色／表面與圖標／無障礙語意，不在 `AppearanceRow` 保留重複 style／色彩組合。
- outfit 的文字仍讀寫 `appearance.usage`；body feature 仍讀寫 `appearance.note`；描述仍綁定 `appearance.descriptionText`。
- 刪除按鈕仍呼叫原 `onDelete`，沒有新增、移除或改變 confirmation／資料副作用。
- `CharacterTimelinePlacementEditor` 和類型 Picker 的資料及互動保持原狀。
- 所有例外及尚未遷移呼叫點列入 V9 inventory。

## U：介面與互動提案

### 實際畫面狀態

已核對使用者提供的深色局部截圖與來源碼：類型選單和刪除圖標在同一列，刪除圖標緊鄰選單，沒有靠到右緣；描述編輯欄、單行欄、時間定位依序向下排列。截圖尚不能測量實際 Button 命中框，也沒有 Light、身體特徵、hover／focus 狀態。U 的位置與資訊架構提案以此截圖為基線，互動範圍仍需實際操作驗收。

### 實際畫面與來源碼對照線框（提案保持此順序）

```text
┌──────────────────────────────────────────────────────────┐
│ 類型 [服裝 Picker：frame 寬 150] [刪除圖標]             │
│ 外觀描述                                                  │
│ [多行描述編輯器；目前 minHeight 110 pt]                   │
│ [服裝：場景／用途；身體特徵：備註]                      │
│ 時間定位     [敘事版本] [時間序版本]                       │
└──────────────────────────────────────────────────────────┘
```

### U 提案：位置與互動

- 沿用截圖所見排列、Picker 原 150 pt frame、描述／單行／時間定位的上下順序；刪除圖標維持緊鄰 Picker，不移到列最右側，不新增 Spacer 或 confirmation。
- 刪除圖標使用共用語意 `.delete` 與「刪除外觀」tooltip／VoiceOver label。圖形仍為 trash，既有 `onDelete` closure、`.destructive` role 與 `.plain` style 保留。
- 互動命中框不可覆蓋類型 Picker、編輯器或時間定位控制；純圖標刪除按鈕需有可讀 tooltip／VoiceOver label。
- outfit／body feature 切換後，欄位仍對應各自既有資料欄位；CJK 組字、鍵盤 focus、文字選取與編輯器捲動需保持原行為。
- 建議刪除按鈕使用共用 `28 × 28 pt` 命中範圍；截圖只能看見圖標，無法證明原命中範圍或新框是否會推動圖標。實作後需在相同寬度畫面比較中心位置與 Picker 間距，並以滑鼠／觸控板確認實際可點範圍；若框造成可見位置變化或相鄰命中重疊，須調整元件而非默認接受。
- 描述維持現有 `InsetTextEditor(minHeight: 110)` 的背景與邊線；單行欄接共用欄位時需保留原條件式 placeholder 與 Binding。截圖沒有證據要求改外觀卡片底色或描述欄尺寸。

## I：已批准的實作計畫

### 預計變更範圍

1. UI foundation 已有 `SailuneIconButton(symbol:label:role:action:)`、`SailuneFormTextField`、`InsetTextEditor`、`SailuneTheme`、`SailuneSymbol.delete` 與 `SailuneActionCopy.deleteAppearance`。本切片預計只改 `CharacterSectionViews.swift` 的 `AppearanceRow`；若條件式 placeholder 無法保持原型別／行為，先調整共用欄位 API 並記錄原因。
2. 刪除按鈕接 `SailuneIconButton(symbol: .delete, label: SailuneActionCopy.deleteAppearance, role: .destructive, action: onDelete)`，仍在 Picker 後；原 `trash` 字形、`.plain` style 與 closure 保留，增加 28 × 28 pt 互動框和明確 help／accessibility label。
3. 原條件式 `TextField` 接 `SailuneFormTextField`，維持服裝 `usage`／身體特徵 `note` Binding 與兩個 placeholder；`InsetTextEditor(minHeight: 110)`、Picker、時間定位、外層 surface 與儲存流程維持原程式。
4. 對照已保存的深色基線，再核對 Light、身體特徵、不同寬度、刪除圖標與 Picker 間距、28 pt 命中、Tab／VoiceOver、CJK 輸入和類型切換。若共用按鈕使圖標明顯移位或 hit area 覆蓋 Picker，先修正 component API，不接受版面回歸。

### 風險與停止條件

- 若一般 `TextEditor` wrapper 改變 CJK 輸入、選取、focus、scroll 或編輯回饋，保留專用 wrapper 或調整 API，不為共用而犧牲輸入行為。
- 若 28 pt 命中框與鄰近 Picker／列內控制重疊，先修正共用按鈕 API 或記錄本列例外，不接受 hit-test 回歸。
- 若需改變刪除 confirmation、持久化責任或時間定位，停止並另立 R／U／I 變更，不納入本批。

### 驗證計畫（程式接線已完成，GUI 待驗收）

- GUI 手動：比較 outfit 與 body feature、淺／深外觀、不同寬度；檢查滑鼠命中、鍵盤 focus／Tab、VoiceOver label、編輯器 CJK 輸入／選取／捲動。
- 資料行為：修改描述、usage、note 後確認各自對應欄位；刪除時確認仍只呼叫原有刪除流程；確認時間定位 unchanged。
- 靜態檢查：`git diff --check`；依實際變更決定是否需既有相關 XCTest。不在這份規劃工作中執行 build 或測試。
