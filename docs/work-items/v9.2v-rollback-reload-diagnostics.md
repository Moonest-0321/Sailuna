# V9.2v rollback 後快取重載錯誤診斷

> 狀態：closed（七處重載失敗均改為明確記錄）

## 工作單元

- 目標：避免 Store 保存失敗並 rollback 後，快取 reload／refresh 失敗被 `try?` 靜默丟棄。
- 範圍：`AbilityProgressStore` 四處、`ItemCopyStore` 兩處、`StoryPlanningStore` 一處失敗 catch。
- 行為：原始保存／遷移／協調錯誤仍作為主要錯誤呈現或重新拋出；若 rollback 後重載也失敗，透過既有 OSLog 介面記錄次要錯誤。
- 非目標：不改錯誤文案、重試政策、資料、持久化順序或畫面狀態；不涵蓋跨 Store 能力建立補償保存。
- 完成條件：七個靜默重載呼叫改為明確 `do/catch` 記錄；原錯誤出口不變；`git diff --check` 與 Debug build 通過。

## R／U／I

| 關卡 | 狀態 | 依據 |
|---|---|---|
| R | approved | 使用者要求 V9 統一內部錯誤處理；本批修正 catch 中次要錯誤被靜默丟棄。 |
| U | not_applicable | 不變更畫面、錯誤提示、資料流程或使用者操作。 |
| I | approved | 只在原 catch 增加次要錯誤診斷，主錯誤仍按既有方式處理。 |

## 驗證與限制

- 2026-09-24：能力進度四處、物品副本兩處及故事規劃一處 rollback 後 reload／refresh 失敗均由 `Logger` 記錄；外層原始錯誤仍維持原呈現或拋出。專案中上述檔案已無 `try? reload()`／`try? refresh()`。
- `git diff --check` 與主機無簽章 macOS Debug build 通過；本批不新增或執行程式測試。故障注入與 log 輸出未在本批驗證。
