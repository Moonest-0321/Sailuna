# 時間軸功能規格

> 狀態：V6.4 已完成單書紀元銜接計算與時間軸排序，並在紀元管理加入整個紀元的協調刪除；V4.4.7 已將寬版世界時間軸改為每事件一格的水平單排；以下 V4.2／V4.4.1 段落為歷史演進
>
> 更新日期：2026-09-22

## V6.4 紀元管理刪除

- 紀元管理每列提供破壞性「刪除」按鈕，先以系統確認提示列出影響範圍；取消不修改資料，確認後才刪除。
- 刪除範圍限於目前這本書的所有時間軸中仍連結該紀元的 Node，以及 Node 底下的 Event；需要保留的時間點須先移至其他紀元。每本書的紀元與設定彼此獨立，不存在多本書共用紀元。
- Node 刪除沿用既有協調規則：清除事件卡 metadata 與 ItemCopy、AbilityProgress、V5 settings 等獨立 store 的失效 Node UUID。主 store 先保存；附屬 store 清理失敗會顯示待修復狀態並由既有冪等修復重試。
- 角色、能力、外觀、心理、物品與關係等歷史來源內容保留，但解除其 Node 時間定位；正文與敘事大綱內容保留。若刪除的 Era 是某本書的 `currentEra`，關聯解除，之後既有 bootstrap 可建立空白預設 Era，不替換成另一個既存 Era。
- 不變更 SwiftData schema、migration、紀元列表範圍／排序或其他紀元管理功能。
- 時間軸項目排序固定先按目前書籍的紀元順序，再按紀元內年／月／日，最後才使用同日 `sortOrder` 與 UUID；不以跨紀元的絕對年份把前紀元晚年與後紀元元年交錯。未指定紀元排在已指定紀元之後。
- 每個日期時間項目右上角提供簡潔 `xmark` 刪除圖示；確認後只刪除該項目所屬的 Node 與其 Event，正文與敘事大綱保留，並沿用既有跨 store 時間定位清理。UI 不加入額外說明文字。
- 驗收：取消保持資料不變；確認後目標 Era、其所有 Node／Event 被刪除，其他 Era 及不屬於該 Era 的 Node／Event 保留；跨 store 清理完成或明確回報待修復。

## V4.4.7 單排事件與末端改元

- 寬版時間軸的每張可見 Event 各占一個固定寬度 slot，同年、同月、同日及同一日期群組的事件都依序向右，不在同一 slot 內垂直堆疊。
- 同日新建事件會取得該日期下一個 `sortOrder`；既有相同排序值仍以 UUID 穩定排序。沒有 Event 的日期 cell 保留一個「尚無事件」slot，有事件時不額外顯示空 slot。
- 日期標籤以展開後的 slot 序列計算；viewport 第一格顯示完整日期，後續依年／月省略。同日多卡仍各自顯示日期，例如日粒度為「4年6月18日｜18日」。
- 時間軸「新增」只保留預排事件與日期節點；「從敘事大綱加入時間軸」移至寬版敘事大綱頂部，沿用原來源、日期、卷節與節錄保存流程。
- 改元不再以可能落後的 `currentEra` 為基準；系統從本書時間軸節點與 currentEra 找出 `startOrdinal` 最大的最末年號，取其最大年份後追加新年號。popover 先顯示接續年號與年份，既有年號與日期不改寫。
- 本版只有顯示投影、入口與新增／改元演算法調整，沒有主 store 或 StoryPlanning schema 變更。
- 後續修正將來源範圍擴充為本書全部既有 OutlineItem；作者先在敘事畫布選定來源，建立表單不允許改選，再輸入具體世界時間並帶入大綱標題／詳情。此建立流程固定使用內文自動節錄，不提供手動自填；沒有正文 anchor 的手動來源仍保存 metadata，但 Event 不綁 Section，卡片以虛線及「尚無正文來源」呈現。

## V4.4.6 世界時間軸卡片

- 寬版世界時間軸以固定 190 點 slot 水平排列日期節點，不按真實時間跨度拉伸；節點仍依世界日期由早至晚排序，同日事件依既有 `sortOrder`。
- 日／月／年粒度保留。水平 viewport 的第一個可見節點顯示完整可用日期，後續節點省略相同年／月；跨紀元重新補齊，捲動只改顯示標籤，不回寫資料。
- 已有有效敘事正文來源，或屬舊資料且仍有本書有效 Section 的事件，以實線卡顯示；未綁定或來源失效者以虛線顯示。
- 卡片包含最多 10 字標題、卷／節、最多 30 字且兩行的節錄，以及右上圓形刪除按鈕。既有超長標題不因升級被截斷，只有新輸入與後續編輯套用限制。
- V4.4.6 原新增選單曾提供三種入口；V4.4.7 起時間軸只保留「新增預排事件」與「只新增日期節點」，敘事項目入口移至寬版敘事大綱。
- 節錄分為動態正文節錄與手動節錄。自動模式依目前 anchor 解析位置擷取 30 個可見字元並壓縮空白；解析失敗退回 anchorText。手動模式保存最多 30 字。
- 卡片詳情可新增、變更或解除敘事項目綁定。失效來源保留 Event 與 metadata，不刪正文；作者可重新綁定。
- 卡片刪除只刪 Event 與卡片 metadata，保留 Node、OutlineItem、anchor、Section 與正文。刪除 Node／Timeline 的既有 cascade 仍會刪 Event，之後冪等清理孤立 metadata。
- 右側窄欄維持 V4.4.5a 唯讀標題清單；窄版原時間軸管理與事件畫面不改。

## V4.4.3 目前行為與驗收

- 寬版及右欄的「時間軸」均使用 `TimelinePanelView`，直接讀寫原有 Timeline／Era／Node／Event；敘事大綱繼續負責正文順序與節奏，不轉換任何 OutlineItem。
- 寬版可用寬度至少 760 點時，左側日期軸、右側選中日期的角色分組事件；更窄及右欄沿用日期列展開。空狀態提示從上方新增時間釘子。
- 保留主／副軸、年／月／日粒度、紀元管理、改元、時間釘子新增／刪除與事件編輯。切換軸或粒度清除舊選取；刪除選中日期後不保留失效詳情。
- 沿用既有日期序位與可見性規則；無年份參考點不顯示，月／日可空白；相同日期但不同紀元不合併。
- 沿用既有刪除規則：刪除軸／釘子會刪除所屬事件，清除相關歷史定位；正文保留。沒有 schema 或資料遷移變更。
- 回歸驗收包含初始化冪等、改元保留舊日期、粒度分組、跨紀元隔離、主／副軸可見性、刪除保留其他軸與正文，以及日期和修改過的事件存檔重開。
- V4.4.4 的寬版時間軸將新增時間釘子、紀元管理、新增副軸、改元、編輯紀元、刪除釘子及事件操作改為文字搭配圖示的較大按鈕；原有可用條件、確認與資料行為不變。右側窄欄不列為本版完成範圍。
- V4.4.5 的寬版時間軸依既有日期投影，以「紀元 → 日期 → Event 標題」垂直顯示；紀元與日期均可個別收合，摺疊狀態不寫入資料。不同紀元的相同日期保持分離，同日期事件沿用 `sortOrder`。
- 事件若有仍屬於本書的有效節次，點擊標題直接返回該節；沒有有效節次則開啟既有事件詳情，不猜測正文位置。主／副軸、粒度、紀元、時間釘子及事件管理入口保留，右側窄欄仍使用原日期展開介面。
- V4.4.5a 的右側時間軸只讀取預設主軸，依完整日期及事件 `sortOrder` 攤平成標題清單；不顯示軸線、粒度、紀元、日期、摺疊或管理控制。事件有本書有效節次時可直接跳轉，否則只顯示標題。寬版時間軸的完整管理行為不變。

## 1. 功能目的

V4.2 讓作者以時間軸形式閱讀並編輯全書大綱；既有世界時間定位資料則繼續讓角色身分、能力、外觀、心理、物品與關係歷史保留原本的時間與章節位置。

## 2. 舊時間定位相容層

- **時間軸（Timeline）**：一本書可有多條時間軸，其中可指定主要時間軸。
- **紀元（Era）**：具有名稱、顏色與起始序位，可套用至時間點。
- **時間釘子（Node）**：包含年、月、日、顯示狀態與排序，並可連結紀元、時間軸與節。
- **事件（Event）**：包含標題、詳細內容、可見狀態與排序，可連結時間釘子、節與角色。

## 3. 相容層已確認行為

- 舊資料模型與歷史 schema 原樣保留；V4.4.3 工作區頂層及右欄重新使用原面板。
- 可建立與編輯時間釘子；年月日可部分留空。
- 未填寫年份的時間釘子不會以「0 年」顯示於世界時間軸。
- 時間釘子可指定時間軸、紀元與節，並可選擇是否顯示於時間軸。
- 歷史資料可透過「時間定位」選擇既有時間釘子或建立新時間戳記。
- 提供角色時間軸投影，用於查看角色資料在時間中的位置。
- 事件可與角色及節建立關聯。

## 4. 待確認決策

- 多條時間軸之間是否需要同步、轉換或平行世界語意。
- 紀元起始序位與年／月／日的換算規則是否需要對使用者公開。
- 使用者補充並確認紀元銜接原則：前一紀元有紀錄的最大年份就是最後一年，下一紀元接續其後；各紀元日期由元年元月一日計算。計算範圍是目前這本書的全部時間軸；每本書的紀元與設定獨立，不存在跨書共享。空紀元目前視作元年，管理頁可手動調整序數。月份／日期不參與年序推進。
- 年份為空時，時間點應被視為參考標記、相對時間，還是未完成資料。
- 跨大綱項目與事件的正式關聯（本版不處理）；事件建立與編輯已沿用原面板提供。
- 時間點衝突、同日排序與跨紀元排序的顯示規則。

## 5. 相容層回歸條件

- 能建立至少一條時間軸與一個時間釘子。
- 能將角色或其他歷史資料定位到該時間釘子。
- 能由時間軸定位回相關節或設定資料。
- 隱藏時間釘子與無年份參考點不會造成錯誤的世界時間顯示。

## 6. V4.2 新時間軸（已實作）

V4.2 工作區頂層時間軸直接顯示 `OutlineItem`，與敘事大綱共用同一筆內容。不同故事線會同時分欄呈現，讓作者比較前傳、主線、支線與後記；第一版不區分敘事順序與世界時間順序，不要求先建立時間釘子，狀態和順序均由作者手動指定。

V4.2 採保留方案：不移除、不改寫、不自動轉換既有 `Timeline`、`Node` 與 `Event`。正文右鍵已不再新增舊版時間軸資料；舊資料仍供既有歷史時間定位相容使用。兩套資料的正式嫁接或相容層退場仍待後續決策。完整產品範圍見 `docs/prd-v4.2-outline.md`。

### V4.4.1 過渡狀態

- 「敘事大綱」已採用同一套幕／節次橫軸與故事線泳道 UI，用於理解正文揭露順序與節奏。
- 「時間軸」頁籤、入口、卡片點擊回正文及現有橫向內容完整保留，本版不改名、不隱藏，也不接回舊曆法資料。
- 因此兩個頁籤在 V4.4.1 可以相似；下一工作單元才以既有紀元、年／月／日、時間釘子與事件為基礎設計真正的世界時間大綱。

### V4.2 驗收條件

- 新時間軸能顯示指定書籍與故事線的大綱項目。
- 新時間軸能同時以獨立欄位顯示多條故事線。
- 四種手動狀態與排序在敘事大綱及新時間軸一致。
- 從任一呈現修改後，另一呈現讀取相同 `OutlineItem`，不產生副本。
- 沒有舊 `Timeline`、`Node`、`Event`、正文或故事標籤時仍可建立、儲存並重開。
- V1→V2 故事規劃遷移及 V4.2 操作不改寫舊時間定位、故事標籤或每節註記。

## 7. V4.4.8 刪除與修復

- 寬版事件卡與既有事件列共用同一確認流程；只刪除世界時間事件，日期節點、敘事大綱與正文保留。
- 刪除時間釘子或副軸會連帶刪除其下事件，但敘事大綱與正文保留。
- 主資料保存失敗時，畫面明示內容仍完整保留；主資料已刪除、僅不可見 metadata 清理延後時保持安靜並由冪等修復重試。
- OutlineItem 來源失效時保留 Event 與 metadata，不推測新的來源，也不連帶刪除世界時間內容。
